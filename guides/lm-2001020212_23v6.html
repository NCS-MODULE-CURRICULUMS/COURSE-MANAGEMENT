알아야 할 것

시스템 인터페이스 정의
시스템 인터페이스는 서로 다른 시스템 간에 데이터를 교환하거나 기능을 호출·제공하 기 위해 프로토콜, 데이터 형식, 처리 로직 등을 정의하고 구현하는 기술 또는 활동을 말한다.
시스템 인터페이스 목적
시스템 인터페이스의 목적은 송신 시스템과 수신 시스템 간의 데이터 교환, 업무 연계, 기능 공유 등을 하는 것이다.
주요 기능 범위
송신 시스템은 데이터를 전송하고, 수신 시스템은 이를 수신하며 필요시 응답 데이 터를 송신 시스템으로 반환하는 기능이다.
시스템 인터페이스 구성 요소
시스템 인터페이스는 송신 시스템, 수신 시스템, 중계 시스템, 프로토콜, 데이터 포맷 등으로 구성된다. 송신 시스템 데이터를 생성·가공하여 인터페이스를 호출하는 시스템 Source System 수신 시스템 송신 시스템으로부터 데이터를 수신하고 처리·저장하는 시스템 Target System
시스템 인터페이스 유형 분류
동작 방식에 의한 인터페이스 유형은 동기 방식과 비동기 방식으로 구분할 수 있다. 처리 방식에 의한 인터페이스 유형은 온라인과 배치 방식으로 구분할 수 있다.
인터페이스 구현 기술
인터페이스 프로토콜을 기반으로 응용프로그램에서 사용할 수 있는 다양한 인터페이스 구현 기술이 존재한다.
인터페이스 데이터 포맷
인터페이스 구현 시 데이터를 전송하기 위해 데이터를 다양한 포맷으로 작성, 변환하여 일반적인 인터페이스 데이터 전달 포맷으로 전송 데이터를 문자열 형태로 조립하여 전송하는 포맷을 말한다.
인터페이스 솔루션
인터페이스 구현은 인터페이스 구현 기술, 데이터 포맷 등에 따라서 상이할 수 있으므로 인터페이스를 통합적으로 등록, 관리할 수 있는 환경 및 기능을 제공하는 다양한 유형의 솔루션이 존재한다.
인터페이스 범위 정의 단계
인터페이스 범위 정의 단계에서는 대상 시스템 식별(내부/외부 시스템), 송수신 주체 식별 및 인터페이스 목적 등을 정의하며, 주요 산출물은 인터페이스 목록 정의서 및 인터페이스 개요서가 있다.
인터페이스 요건 정의 단계
인터페이스 요건 정의 단계에서는 데이터 발생·수신 조건, 데이터 발생 주기(실시간, 배치), 트랜잭션 범위, 데이터 볼륨 예측, 성능 요건(응답 시간, 동시 처리량) 등을 정의하며, 주요 산출물로는 인터페이스 요구사항 정의서가 있다.
인터페이스 상세 설계 단계
인터페이스 설계 단계에서는 데이터 항목 명칭, 타입, 길이, 필수 여부, 암호화 여부, 민감정보 식별, JSON, XML, ProtoBuf, CSV 등 포맷 결정, 오류 코드, 에러 시 재처 리 정책 등을 결정하며, 주요 산출물로는 인터페이스 상세 설계서, 데이터 매핑 명세서 전문(메시지) 레이아웃 정의서 등이 있다.
연계 방식 설계
연계 방식 설계에서는 API 명세(OpenAPI/Swagger), ESB, EAI, API Gateway 활용 여부 결정, 시퀀스다이어그램 작성, 엔드포인트 설계(URL, Method, Parameter 등) 등을 하며, 주요 산출물로는 API 명세서, 연계 시퀀스다이어그램, 인터페이스 구성도 등이 있다.
테스트 설계 단계
테스트 설계 단계에서는 테스트 케이스 작성, Mock Data 생성, 예외 시나리오 정의 등을 하며, 주요 산출물로는 인터페이스 테스트 시나리오, 테스트 데이터 세트 등을 준
운영 관리 설계
운영 관리 설계 단계에서는 장애 모니터링 항목 선정, 로그 관리 체계 수립, 운영 시 대처 시나리오 작성 등을 하며, 주요 산출물로는 운영 가이드, 모니터링 설계 문서 등 - 인터페이스 대상 시스템 식별 - 인터페이스 목록 정의서 - 송수신 주체 식별 - 인터페이스 개요서 - 인터페이스 목적 정의 인터페이스 - 인터페이스의 데이터 항목 식별 - 인터페이스 요구사항 정의서 / 인터페이스 설계서

시스템 간 인터페이스 개발 시 각기 다른 팀이나 벤더, 외부 기관 간에도 공통된 규칙을 적용해 데이터 정합성과 통신 표준화를 유지하기 위한 기준을 설정한다.
기업 내 인터페이스 표준 중요성
시스템 간 데이터 교환의 상호 호환성, 유지보수성, 운영 안정성을 확보하기 위해 필요 한 기술, 프로토콜, 데이터 규격, 처리 규칙 등을 통합적으로 규정하며, 기업 내에서는 내부 시스템 및 외부 기관과의 인터페이스의 상호 호환성, 운영 안정성 및 유지보수성 향상을 위해서 인터페이스 적용 기술, 인터페이스 솔루션, 인터페이스 데이터 항목을 표준화한다.
애플리케이션 간 인터페이스 원칙
기업 내에서는 애플리케이션 간 체계적인 인터페이스 구현 및 관리를 위해 인터페이스 유형에 따른 인터페이스 원칙을 정의하여 관리한다.
인터페이스 데이터 구조 표준
기업 내 인터페이스 운영 중 로그 추적 및 오류 발생 시 원인 파악을 가능하게 하는 공통 데이터 구조를 말한다.
인터페이스 데이터 표준
인터페이스 데이터 표준은 시스템 간 데이터 교환 시 데이터 항목명, 데이터 형식, 데이터 길이, 의미, 값의 범위 등을 일관되게 정의하고 관리하는 규칙으로서, 데이터의 정확성, 무결성, 호환성을 확보하고 시스템 간 데이터 매핑과 변환 비용을 최소화하기 위한 필수 요
데이터 표준 개념
데이터 표준이란 시스템 내에서 데이터 저장, 처리 및 인터페이스 시 전달되는 데이터 들의 형식과 명칭을 말한다.
데이터 표준 중요성
시스템의 일관된 개발, 데이터 중복 방지 및 오류 방지를 위해서 데이터 표준을 준수하는 것이 필요하다. 데이터 표준은 표준 용어와 도메인으로 구성된다.
표준 용어
업무에서 사용하는 명사형 용어를 정리한 표준 단어 집합을 의미한다. 표준 용어 사용을 통해서 시스템 내에 사용되는 칼럼, 변수명, 인터페이스 데이터 항목 등에 대해 의미를 분명하게 정의하고 이음동의어의 사용을 방지하며, 단어 의미를 명확히 하여 개발 생산성을 향상시킬 수 있다.
표준 도메인
도메인은 각 용어 속성의 특징, 유형을 분류한 것으로 번호, 코드 등의 데이터 유형을 말한다. 도메인에는 해당 도메인에서 허용되는 데이터 타입, 길이, 허용되는 값의 범위에 대한 정의가 포함된다.
인터페이스 데이터 변환
송수신 시스템 간 데이터 표준이 다를 경우, 데이터 변환(Mapping, Transformation) 을 통해 호환성을 확보한다.
인터페이스 내 데이터 표준 예시
송수신 시스템 내 인터페이스 대상 프로그램에서 사용하는 데이터 표준을 바탕으로 인터페이스 데이터 표준을 정의하고 산출물에 표현한다.

인터페이스 개발 환경
기업에서 일반적인 인터페이스 개발은 인터페이스 솔루션을 사용하여 개발되며, 인터페이 스 솔루션은 효율적인 인터페이스 개발을 위한 개발 환경을 제공한다.
인터페이스 구현 방법
인터페이스 구현 방식은 여러 가지가 있지만 대표적인 방법으로는 온라인 서비스 호출을 이용한 구현, 인터페이스 테이블을 이용한 구현 및 배치 프로그램을 통한 구현 방법으로나눌 수 있다.
온라인 서비스 호출을 통한 인터페이스 구현
송신 시스템의 온라인 프로그램에서 인터페이스 형식에 맞춘 데이터 포맷을 수신 시 스템의 온라인 프로그램 인터페이스를 대상으로 전송하고 이를 수신 측에서 파싱 (Parsing) 하여 해석하는 방식이다.
데이터베이스 테이블을 통한 인터페이스 구현
인터페이스 송신, 수신 시스템 사이에 별도의 인터페이스 테이블을 두어 인터페이스를 구현하는 방식이다. 데이터베이스 접속 API를 통해서 각 시스템의 데이터베이스에 접속해서 테이블 내의 데이터값을 송수신한다.
배치 프로그램을 통한 인터페이스 구현
인터페이스에서 주고받은 데이터의 크기가 크거나 데이터 건수가 많은 경우 데이터 내역을 파일 또는 데이터 구조체로 분할하고 별도의 배치 프로그램을 통해서 인터페이 스를 수행할 수 있다.

인터페이스 공통 기능의 구성
시스템 간 인터페이스를 구현하고 런타임 환경에서 동작 시 발생하는 오류를 적절하게 예외처리를 하기 위해서는 다음과 같은 공통 기능이 필요하다.
인터페이스의 주요 보안 취약점

데이터 암호화

재료·자료모듈 세부 설계서(컴포넌트 명세서, 인터페이스 명세서), 인터페이스 정의서, 정적･동적 / 모형 설계도, 식별된 인터페이스 기능, 인터페이스 데이터 표준, 구현된 인터페이스 / 인터페이스 검증 및 감시 도구 / 애플리케이션, 네트워크, 보안, 서버 구성 지식 및 자료 / 시스템에 대한 요구사항 정의서, 아키텍처 구성도기기·도구전산 장비: 인터넷, 컴퓨터, 프린터, 복사기, 빔 프로젝터 등 / 지원 도구: 문서 작성 도구, 문서 발표 도구유의 사항다양한 오류 사항 확인 방법의 장단점을 숙지하고 오류 사항을 확인하여야 한다. / 86 / 오류 보고는 오류 보고서 양식에 맞추어 신속하고 명확하게 작성하여야 한다. / 학습을 통하여 도출된 결과는 반드시 재평가하여 피드백한다. / 인터페이스 오류 처리 확인 및 보고서 작성하기는 각기 주관적일 수 있으니 토의를 통 / 하여 자신이 산출한 결과에 대하여 상호 검증을 받는다. / 토의를 진행할 때에는 비판적인 자세보다는 더 나은 생각을 개진하는 생산적인 방향으로 / 진행하여야 하며, 상대방의 비판 및 의견을 열린 마음으로 수용하는 자세가 중요하다.
1인터페이스 동작 상태를 확인한다.
  1. 외부 시스템과 인터페이스 모듈의 동작 상태를 확인한다.
  2. 최초 데이터 입력과장 xx명 입사 발령 확정 xx명의 사번이 확정 FLAG를 가지고 저장 예상값과 동일
  3. DB에서 조회 입사자 과장 xx 명 정보 조회 xx명의 인사 발령 정보, 기본 정보 선택 예상값과 동일 생성 전송 버튼 클릭 DB에서 조회된 동일 정보가 확정된 xx명에 대해서 JSON 생성 예상값과 동일 전송 xx명 과장 입사 발령 확정 내용 송신 이력 적재 예상값과 동일
  4. 수신 및 파싱 수신된 객체를 파싱한 결과와 송신 결과 동일 예상값과 동일 트랜잭션 수신 회사 인사 정보로 입력 파싱된 결과는 수신 측의 프로그 램 처리 순서에 따라 처리 예상값과 동일 반환 전송 회사 입사 자 정보 조회 - 수신 결과 송신 측 반환 - 이력 테이블에 해당 내역 입력 예상값과 동일
  5. 외부 시스템과 인터페이스 모듈의 동작 상태를 감시한다.
  6. 인터페이스 수행 내역을 확인한다.
2인터페이스 오류 사항을 확인한다.
  1. 인터페이스 오류 내역을 확인한다.
  2. 상세 오류 내역을 확인한다.
  3. 인터페이스 오류 사항에 대해서 사후 처리를 수행한다.
  4. 인터페이스 오류 발생 내역을 분석한다.
3인터페이스 오류 처리 보고서를 작성한다.
  1. 인터페이스 오류 처리 보고서를 작성하고 보고한다.

스스로 확인

  • 인터페이스 동작 상태를 확인한다.
  • 인터페이스 오류 사항을 확인한다.
  • 인터페이스 오류 처리 보고서를 작성한다.
  • 인터페이스 구현 검증을 위하여 외부 시스템과의 연계 모듈 상태를 확인할 수 있다.
  • 인터페이스 오류 처리 사항을 확인하고 보고서를 작성할 수 있다.

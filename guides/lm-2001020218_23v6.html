알아야 할 것

인터페이스 요구사항
인터페이스 요구사항은 목표 시스템과 외부 시스템을 연결하는 시스템 인터페이스와 사용 자 인터페이스에 대한 요구사항으로 분류할 수 있다.
시스템 인터페이스 요구사항
시스템 인터페이스란 서로 독립적으로 운영되는 시스템 간에 연동을 통해 정보를 교환하고 상호 작용 할 수 있도록 정의된 접속 방식과 규칙을 의미한다.
시스템 인터페이스 요구사항 분석
- 시스템 인터페이스 요구사항 분석은 요구사항 정의 단계에서 정의한 기능 및 비기능 인터페이스 요구사항을 상세하게 이해하고, 요구사항을 분류하고 조직화하여 명세를 구체화하는 작업이다.
요구사항 분석
요구사항 분석은 도출된 기능 및 비기능 요구사항을 분석하여 상세하게 이해하고, 요구사항을 만족시키기 위한 아키텍처 구성 요소를 식별하거나 중요도에 따라 우선순위를 부여하는 등 요구사항을 구체화해 나가는 일련의 과정이다.
요구사항 분석 기법
요구사항 분석 기법에는 요구사항 분류, 개념 모델링을 통한 요구 기능 분석, 요구사항 할당, 요구사항 협상 등이 있다.
요구사항명세서
요구사항 분석을 통해 확정된 요구사항명세서는 시스템 개발 작업의 기준선(Baseline) 으로 활용될 수 있으므로 요구사항 확인(Validation) 및 검증(Verification), 비용 추정 등의 작업이 가능하도록 명확하고 완전하게 정의되어야 한다.

1인터페이스 관련 요구사항을 식별하고 관련 자료를 수집하여, 기능과 비기능 요구사항으로 분류한다.
  1. 요구사항목록을 검토하여 인터페이스 관련 항목을 식별한다.
  2. 인터페이스 관련 자료를 수집한다.
  3. 인터페이스 요구사항을 기능 요구사항과 비기능 요구사항으로 분류한다.
2인터페이스 요구사항 정의서와 관련 자료를 기반으로 기능 및 비기능 요구사항을 분석하고 요구
  1. 인터페이스 요구사항을 검토하여 분해가 필요한 경우 적절한 수준으로 세분한다.
  2. 인터페이스 요구사항 정의서를 검토하고, 필요시 내용을 수정하거나 보완한다.
  3. 관련 자료를 종합하여 누락된 요구사항을 도출하고, 인터페이스 사항을 보완한다.
  4. 수정 및 추가된 인터페이스 요구사항을 정리하고, 명세서에 반영한다.

알아야 할 것

요구사항 검증(Verification)
요구사항 검증(Requirements Verification)은 요구사항명세서에 사용자의 요구가 올바르 게 기술되었는지에 대해 검토하고 베이스라인으로 설정하는 활동이다.
요구사항 검증 절차
요구사항 검증은 요구사항 검토 계획을 수립하고 고객과 분석가 등 다양한 이해관계자 들과 함께 다양한 시각에서 공식적으로 검토하고 승인해야 한다.
대내외 연계 시스템을 모두 식별하고, 인터페이스 요구사항을 누락 없이 도
출하였는가?
업무 범위서 및 프로젝트 수행 계획서와 비교하여 범위를 벗어나는 연계 시
스템의 경우 인터페이스 방안을 검토하였는가?
송수신 데이터의 암호화가 필요한 경우 적용 가능 알고리즘을 기술하였는가?
요구사항 검토를 통해 검증된 요구사항은 공식적으로 승인되며, 이를 기반으로 소프 트웨어 설계와 구현이 가능하도록 요구사항명세서의 베이스라인을 설정한다.
요구사항 검증 방법
요구사항 검토 담당자들이 요구사항명세서를 수작업으로 분석하는 방법으로 요구사 항명세서에 오류가 없는지, 불명확한지, 표준을 준수했는지 등을 검토한다.

  6. 인터페이스 요구사항 검토 일정을 수립하고 참석자들과 공유한다.
2인터페이스 요구사항을 검토하고 오류를 수정한 후 요구사항 베이스라인을 설정한다.

  2. 요구사항명세서를 체크리스트에 따라 검토하고 결함을 발견한 경우, 결함 목록과 시정 조치서를 작성한다.
  3. 데이터 항목 정의 및 포맷 수납·이체·환불 데이터 수신 및 정산 데이터 수집 명시, 데이터 항목·형식 미정의 누락 정산 항목(예: 수납 일시, 금액, 거래 ID 등) 상세 정의 필요로직 거래 오류 시 재전송 요청 기능, 응답 코드에 따른 예외처리 로직 필요로 기술됨이상 없음 정의 전송 방식, 주기, 예외 사항 언급 있으나 데이터 전송 크기, 처리 시간 조건 미정 미흡 전송 단위(예: 건수 기준 제한), SLA 기준 등 제약조건 추가 필요 및 산출물 명시 명세서, 정산 로직 처리 설계서 명시이상 없음
  4. 인터페이스 요구사항 검토 결과 공유 및 요구사항 품질 평가를 진행한다.

개발하고자 하는 응용소프트웨어의 내부와 외부 인터페이스를 위해 필요한 송수신 데이터를 식별할 수 있다.

능력단위요소

인터페이스 대상 식별하기

학습모듈

원문 44쪽

분량

개념 8항목 · 실습 6절차

이 꼭지를 마치면

  • 개발하고자 하는 응용소프트웨어의 내부와 외부 인터페이스를 위해 필요한 송수신 데이터를 식별할 수 있다.

알아야 할 것

식별 대상 데이터
송수신 시스템 사이에서 교환되는 데이터는 규격화된 표준 형식(표준 전문)에 따라 전송된 다. 인터페이스 설계 단계에서 송수신 시스템 간에 전송되는 표준 항목과 업무 처리용 데이터(전송 내용) 및 대내외 연계 시 사용하는 공통 코드 정보 등을 누락 없이 식별하고 인터페이스 명세서를 작성해야 한다.
인터페이스 표준 항목(공통 항목)
인터페이스 표준 항목은 대내외 연계를 수행하기 위해 필요한 표준 송수신 메시지의 길이, 송수신 메시지 구성에 필요한 시스템 정보와 전송 관리에 필요한 공통 정보 등을 시스템 공통부는 시스템 간 연동 시 필요한 공통 정보를 말하며, 인터페이스 ID와 전송 시스템 정보(IP 주소, 시스템 코드, 포트 번호 등)와 서비스 코드 정보(수신 시 스템에서 호출할 서비스 ID, 송신 시스템의 서비스 ID
송수신 데이터 항목(개별 항목)
송수신 시스템이 업무를 수행하는 데 사용하는 데이터를 말하며, 인터페이스별로 전송 되는 데이터 항목과 순서가 다르다.
공통 코드
대내외 연계 시 사용하는 공통 코드와 연계 시스템 또는 연계 SW에서 사용하는 상태 코드와 오류 코드 등과 같은 공통 코드 항목에 대해 코드값과 코드명, 코드 설명 정보 등을 공통 코드로 관리해야 한다.
데이터베이스 산출물
본 절에서는 인터페이스 설계를 위해 필요한 데이터베이스 산출물을 간략하게 소개한다. 데이터베이스 산출물에 대한 상세한 내용은 학습모듈 ‘DB 엔지니어링 논리 데이터베이 스 설계(LM2001020403_19v4)’와 ‘물리 데이터베이스 설계(LM2001020404_19v4)’ 등을 참조한다.
개체 정의서
개념 모델링 과정에서 도출한 개체 타입과 관련 속성, 식별자 등에 대한 개괄적인 정보를 포함한다. 개체 타입명은 데이터베이스에 저장할 개체를 대표할 수 있는 이름이고 속성은 개체의 특징 또는 설명할 수 있는 정보, 식별자는 해당 개체를 유일하게 식별할 수 있는 속성(주식별자, 대체 식별자)을 의미한다.
테이블 정의서
테이블 정의서는 논리 및 물리 모델링 단계에서 작성하는 산출물로, 테이블에서 관리되는 칼럼들의 특징(칼럼명, 데이터 타입, 길이, Null 여부, Key 여부, Default값), 인덱 스, 업무 규칙을 문서화한 것이다.
코드 정의서
코드성 속성은 속성명 뒤에 ‘코드’를 붙여서 구별하며 알파벳과 숫자를 조합하여 일정 한 길이로 구성한다. 코드는 전체 데이터베이스에서 유일하게 정의해야 하는데 이러한 코드 정의를 문서화한 것이 코드 정의서이다.

알아야 할 것

연계 방식과 연계 기술
연계 방식은 직접 연계 방식과 간접 연계 방식으로 분류할 수 있다. 직접 연계 방식은 중 계 서버나 솔루션을 사용하지 않고 송신 시스템과 수신 시스템이 직접 인터페이스 하는 방식이다.
직접 연계 방식
직접 연계 방식은 중간 매개체가 없으므로 일반적으로 연계 처리 속도가 빠르고 구현이 단순하며 개발 비용과 개발 기간이 짧다는 장점이 있다.
간접 연계 방식
간접 연계 방식은 EAI(Enterprise Application Integration) 서버와 같은 연계 서버를 활용하여 송수신 처리와 현황을 모니터링·통제하는 방식이다.
연계 기술
시스템 연계 기술은 데이터베이스에서 제공하는 Link를 이용하거나 JDBC, Socket, Web Service 등을 이용하는 방법이 있으며, 시스템 인터페이스 설계 시에는 연계 아키텍처에서 제시한 표준 기술을 이용한다.
통신 유형
통신 유형은 단방향 통신과 양방향 통신, 동기 및 비동기 방식으로 구분된다. 인터페이스 설계 및 구현 시에는 인터페이스 표준을 참조하여 진행한다.
데이터 암호화 필수 항목
‘정보통신망법’과 ‘개인정보보호법’ 등 법률로 정한 암호화 필수 항목이 인터페이스를 통해 교환되는 경우에는 적절한 암호화 방법을 선정하고 데이터 송수신 과정에서 암･복호화 처리를 해야 한다.
인터페이스 오류 유형
시스템 연계 과정에서 발생할 수 있는 장애나 오류 유형은 연계 시스템(연계 서버나 엔진)의 오류와 송신 시스템의 연계 프로그램 오류 또는 수신 시스템의 연계 프로그램 오류, 연계 데이터 자체 오류 등으로 구분할 수 있다.
인터페이스 처리 방법
인터페이스 오류가 발생한 경우, 연계 서버와 송수신 시스템의 로그 파일에 오류 코드와 에러 발생에 대한 상세 내용을 기록하도록 연계 프로그램을 작성한다.

인터페이스 설계서는 인터페이스 목록과 인터페이스 정의서로 구성된다.
인터페이스 목록
인터페이스 목록은 연계 업무와 연계에 참여하는 송수신 시스템의 정보, 연계 방식과 통신 유형 등에 대한 정보를 포함한다.
인터페이스 정의서
인터페이스 정의서는 송신 시스템과 수신 시스템 간의 연계 목적, 범위, 연계 방식 및 전제 조건 등을 포함한다.

1인터페이스 방법 명세화 과정에서 작성한 인터페이스 목록과 송수신 방법, 송수신 데이터 명세
  1. 인터페이스 설계 가이드와 인터페이스 설계서 작성 양식을 준비한다.
  2. 개요(Overview) 요구사항 정의서를 바탕으로 업무 시스템과 외부 시스템 및 대외 기관 간에 데이터를 주고 받는 경우의 인터페이스에 대해 기술한다.
  3. 개요(Overview) 시스템 인터페이스 단위로 시스템 간의 연계를 위해 필요한 데이터 항목 및 구현 요건을 체계적으로 정리한다.
  4. 인터페이스 식별(분석) 단계에서 정의한 인터페이스 기본 정보를 기반으로 인터페이스 목록 양식에 맞추어 내용을 작성한다.
  5. 인터페이스 정의서 작성 양식에 맞춰 송수신 시스템의 정보를 각각 작성한다.
  6. 인터페이스 식별 단계에서 작성한 서비스의 프로그램 명세서를 기반으로, 다음 항목들이 누락 없이 정의되었는지 점검한다.
  7. 인터페이스 설계서 작성 양식에 맞춰 송수신 데이터 항목 상세를 작성한다.
  8. 연계 데이터의 일관성과 정확성을 확보하기 위해 인터페이스 정의서에 매핑 규칙을 명확히하고, 표준 코드 매핑 테이블을 별도로 작성하여 데이터 변환 기준으로 활용한다.
  9. 인터페이스 설계 내용을 검토하고, 품질 관리 절차를 수행한다.

  • 소프트웨어 아키텍처에서 정의한 인터페이스 설계 기준에 따라 외부와 내부 시스템 간의 인터 페이스 설계서를 작성할 수 있다.

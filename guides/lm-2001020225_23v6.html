알아야 할 것

UI(User Interface)
사용자가 하드웨어나 시스템에 연결되는 과정에서 사용자의 편리성과 가독성을 높여 주기 위한 것이다.
CLI(명령어 라인 인터페이스, Command Line Interface)
사용자와 시스템이 상호작용을 하는 방식으로 명령과 출력이 텍스트 형태로 표현된다.
GUI(그래픽 유저 인터페이스, Graphical User Interface)
사용자가 컴퓨터의 자원을 사용할 수 있도록 구성 요소들이 그래픽 형태로 표현된다.
NUI(자연어 유저 인터페이스, Natural User Interface)
몸짓, 말소리만으로도 IT 기기를 사용할 수 있는 사용자 인터페이스이다.
UI 표준은 시스템 전반에 걸쳐 모든 UI에 공통적으로 적용되는 내용을 의미하며, 화면 구성
내용이나 화면 이동 등이 포함된다.
소프트웨어 아키텍처(Software Architecture)
소프트웨어 구성 요소 중 외부에 드러나는 요소 특성과 요소들 간의 관계를 표현한 것
개발과 관련된 정책이나 업무 규칙, 특정 소프트웨어나 프로그램의 사용, 데이터 사용과 관련
된 제약 등에 대한 기술 제약사항(Technical constraints), 개발할 때 적용할 업무 영역의 표준이나 법규의 표준 적합 제약사항(Standard compliance constraints)으로 나눌 수 있다.
화면 설계
파워포인트(Powerpoint), 스토리보드(Storyboard), 와이어프레임(Wireframe), 목업 (Mockup) 등이 있다.
프로토타입(Prototype)
인터랙션(Interaction, 상호작용)이 포함되어 테스트가 가능한 형태이다.
UI 디자인
화면의 모양이나 기능 등을 표현하는 것이다. 숙 UI 설계서 웹사이트의 페이지 구성 요소를 기록한 설계도이다.
함께 나오는 것
UI 표준 및 지침 · UI 지침은 UI 개발 과정에서 UI 요구사항이나 구현 제약사항 등 지켜져야 할 공통의 조건을 · 제약사항(Constraints Requirements) · 시스템을 설계하거나 구현할 때 관련되는 기술이나 표준, 규정들을 의미한다.

알아야 할 것

특정한 목적을 성취하고자 하는 특정 사용자들에 의해 어떤 제품이 사용될 때와 같은 특정한
맥락의 사용에서의 효과성, 효율성, 만족도에 관한 것이다(출처 : ISO 9241-11, 2001).
유용성(Usefulness)
사용자가 업무를 수행하는 데 있어 얼마나 정확하게 수행할 수 있는지를 나타내는 것이다.
설계 단계에서 사이트를 구성하는 처리 내용이나 메뉴의 구조를 표현함으로써 사이트의 구조
를 파악할 수 있도록 하는 것으로 사이트 맵이라고도 한다.
정보 구조를 표현하는 방법에 따라 계층적 구조, 계열 구조, 그리드 구조, 네트워크 구조 등
으로 나뉜다.
내비게이션은 메뉴, 버튼, 링크 등으로 구성되며 이들 구성 요소는 모든 페이지에서 일관성
을 지켜 사용자로 하여금 혼동되지 않도록 하고, 사용자가 직관적으로 자신이 찾고 있는 정보를 알고 찾아가는 데 도움을 줄 수 있도록 설계되어야 한다.
사용자 측면에서의 요구사항이며 주로 기능 개선에 대한 내용으로, 사용자가 원하는 목표를
위하여 시스템에서 수행해야 하는 내용을 기술한다.
하나의 단위 업무에 대한 독립적인 기능을 수행할 수 있도록 표현한다.
유스케이스명 유스케이스의 전체적인 개요가 되는 내용 기술 유스케이스 실행의 주인공(예. 학생 또는 교수 등) 해당 유스케이스의 중요도를 표시 실행 전 조건 해당 유스케이스가 실행되기 전에 갖추어야 할 조건을 기록 실행 후 조건 해당 유스케이스가 실행된 후 결과로 나타나야 하는 조건 흐름(시나리오) 오류가 없는 정상적인 흐름을 기록 정상적인 기본 흐름에서 벗어나는 예외의 경우 기록 기타 요구사

안전･유의 사항
요구사항명세서와 제약사항에 포함된 항목(기능, 성능, 인터페이스, 표준 지침 등) 등이 포함
되었는지 확인한다. 요구사항이 동일한 의미를 가지고 일관성 있게 제시되고 있는가? 요구사항이 정확하게 기재되어 있는가? 요구하는 기능 등이 모두 포함되어 있는가? 요구사항들이 기능적인 면이나 내용적인 면에서 서로 충돌되는가? 요구사항의 내용이 객관적이고 구체적인가? 요구사항을 구현하기 위해 일정, 비용, 구현 등이 가능한가?
개발 팀과 디자인 팀 등 개발 관련 팀 모두가 화면 구현 과정에서 항상 참고할 수 있도록
정리된 자료를 공유한다.
공유된 자료는 소프트웨어 개발 과정에서 표준과 지침의 범주에서 벗어나지 않도록 UI 표준
과 지침을 숙지하도록 한다.
설계 단계에서 UI 표준과 지침이 반영되어 화면 설계가 이루어졌는지 확인하고, 화면 구현을 위
한 기본 사항을 점검한다.
화면을 구성하는 각 페이지마다의 요소(로그인/로그아웃 등)들이 통일성이 유지되도록 설계되

전자정부 웹사이트 이용자가 특정 운영 체제나 웹 브라우저에 상관없이 접속할 수 있도록, 정부에서 전자정부 시스템 구축 시 반영해야 하는 최소한의 규약을 정의한 것이다.
웹 표준(Web Standards)
웹에서 사용되는 기술이나 규칙을 의미하며 웹사이트를 작성할 때 이용하는 HTML, CSS, JavaScript 등에 대한 규정과 다른 기종이나 다른 플랫폼에서도 웹페이지가 구현 되도록 제작하는 기법 등을 포함한다.

어떠한 사용자(장애인, 노인 등), 어떠한 기술 환경에서도 사용자가 전문적인 능력 없이 웹사이트에서 제공하는 모든 정보에 접근할 수 있도록 보장하는 것을 뜻한다.

서비스 이용자 단말기의 하드웨어 및 소프트웨어 환경이 다른 경우에도 동등한 서비스를 제공하는 것을 의미한다.

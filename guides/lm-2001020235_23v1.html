알아야 할 것

자료구조 개념
김진수(2023), Cormen(2009) 등의 연구에 따르면 자료구조는 자료를 저장하고 조직하여 효율적인 접근 및 처리를 가능하게 하는 방식을 의미하며 알고리즘을 적용하여 프로그램의 성능과 효율성에 결정적인 영향을 미치는 요소로 정의한다.
자료구조별 연산 성능 및 복잡도 분석
입력 데이터 크기(n)에 따라 알고리즘 또는 연산 실행 과정의 소요 시간 증가율을 수학적으로 표현한 것으로 Cormen(2009)의 연구에서 언급하고 있는 Big-O 표기 법을 사용한다.
자료구조 알고리즘 종류
데이터 집합에서 원하는 값을 찾기 위한 알고리즘이다. 데이터를 오름차순, 내림차순 등 정해진 순서로 재배열하기 위한 알고리즘이다.
프로그래밍 언어별 자료구조
자바는 컬렉션 프레임워크를 통해 다양한 자료구조를 표준 라이브러리로 제공한다.

알아야 할 것

Big-O 표기법
알고리즘이나 연산의 시간, 공간 복잡도를 수학적으로 표현하는 방법으로 입력 크기 n이 커질 때 연산량이 증가하는 정도를 추상적으로 나타내는 표기법이다.
알고리즘 성능 분석 기준
소스 코드의 반복문, 조건문, 재귀 호출 등을 기준으로 입력 크기 증가에 따른 연산 량을 측정하여 복잡도를 산정한다.
공간 효율성 개념
알고리즘이나 자료구조가 메모리를 효율적으로 사용하는 정도를 나타내는 척도로 임베디드, 모바일 환경 등에서 중요하게 고려해야 한다.
기능별 자료구조 매핑 방법
애플리케이션에서 구현할 기능의 특성과 데이터 흐름을 고려하여 가장 적합한 자료구조를 선택하는 과정이다. 이 과정을 통해 기능의 처리 속도를 높이고, 메모리 사용을 최적화하며, 유지 보수성을 강화할 수 있다.

알아야 할 것

정렬 알고리즘 정의
주어진 데이터를 특정 기준에 따라 재배열하는 과정으로 일반적으로 데이터 탐색, 분석, 저장 최적화에 앞서 필수적인 작업을 실행하는 알고리즘이다.
정렬 알고리즘의 유형 및 동작 원리
비교 기반 정렬 알고리즘은 원소 간의 크기를 비교하여 순서를 결정하는 알고리즘 원소값의 자릿수, 빈도 등과 같은 특징을 이용해 정렬하는 알고리즘이다.
정렬 알고리즘 분류 기준
비교 기반/非비교 기반 비교 기반: 버블, 퀵, 병합 非비교 기반: 기수, 계수 정렬 인접한 두 원소를 비교해 교환하며 가장 큰값을 뒤로 보내는 과정을 반복 구현이 간단하지만 속도가 느림 전체에서 최솟값을 찾아 맨 앞 또는 맨 뒤와 교환하며 정렬 교환 횟수 적지만 속도이미 정렬된 구간에 새로운 원소를 적절한 위치에 삽입 데이터가 거의 정렬된 경우 효율적임 재귀적/반복적 퀵 정렬 등 재귀적 구
응용 알고리즘 활용 사례
기본적인 정렬 및 탐색 알고리즘 외에도 산업 현장에서 다양한 응용 알고리즘이 사용되며, 이는 <표 2-5>와 같다.

1데이터를 정렬하기 위한 알고리즘을 선택한다.
  1. 정렬 알고리즘의 세부 종류와 특성을 정리한다.
2인접한 두 요소를 비교하여 오름차순 또는 내림차순으로 정렬
3한 번의 패스에서 가장 큰 값을 맨 뒤로 버블처럼 이동시킴
4총 n-1번의 패스를 통해 정렬 완료
5간단하고 구현이 쉬움
6대부분의 경우 효율이 낮음
7이미 정렬된 경우에도 모든 비교를 수행
8전체 배열에서 가장 작은 값을 선택하여 맨 앞과 교환
9첫 번째부터 마지막 전까지 반복하여 정렬
10비교 횟수는 항상 동일하며 교환 횟수는 버블 정렬보다 작음
11동일값의 순서 보장이 되지 않음
12왼쪽에서 오른쪽으로 진행, 현재 값을 앞의 정렬된 부분과 비교하여 적절한 위치에 삽입
13작은 배열이나 부분적으로 정렬된 데이터에 유리함
14이미 정렬된 데이터에 대해 매우 빠르며, 동일값의 순서가 유지됨
15쉬운 구현, 실시간 입력 처리에 적합함
16피벗을 하나 선택, 피벗보다 작은 값은 왼쪽, 큰 값은 오른쪽으로 분할
17양쪽 리스트에 대해 재귀적으로 정렬 수행
18분할이 끝나면 각 분할을 병합 없이 결합
19평균 시간 복잡도: O(n log n)
20최악 시간 복잡도: O(n2), 이미 정렬된 경우
21공간 복잡도: O(log n), 재귀 호출 스택
22비안정 정렬, 실제 매우 빠르며, 가장 많이 사용됨
23리스트를 반으로 나누어 재귀적으로 정렬
24나뉜 리스트를 정렬된 상태로 병합함
25병합 과정에서 두 리스트를 비교하며 하나의 리스트로 만듦
26평균 및 최악 시간 복잡도: O(n log n)
27공간 복잡도: O(n), 병합 과정에 임시 배열 필요
28안정 정렬, 데이터 크기가 크고 외부 정렬이 필요한 경우에 적합
29구현은 간단하지만 메모리 소비가 큼
30입력 배열을 최대 힙/최소 힙으로 구성
31최댓값 또는 최솟값을 꺼내어 마지막 값과 교환
32힙 속성을 유지하도록 재정렬
33이를 반복하여 정렬된 배열 생성
34시간 복잡도: O(n log n), 평균/최악 동일
35공간 복잡도: O(n), 제자리 정렬 가능
36비안정 정렬, 삽입 및 삭제가 빈번한 경우 유리
37데이터가 완전한 정렬 상태일 필요 없음
38정렬 대상 숫자를 자릿수 기준으로 정렬
39자릿수마다 안정 정렬 알고리즘을 사용하여 정렬
40가장 낮은 자릿수부터 가장 높은 자릿수까지 반복
41시간 복잡도: O(k-n), k는 자릿수
42공간 복잡도: O(n + k)

44문자열 정렬에 적용 가능하며 실수/음수에는 직접 적용 어려움
  1. 정렬 대상 데이터 특성을 분석한다.

정렬된 데이터에서 원하는 것을 찾기 위한 탐색 알고리즘을 선택할 수 있다.

알아야 할 것

선형 탐색(Linear Search)
데이터를 처음부터 끝까지 차례대로 비교하여 원하는 값을 찾는 방식이다. 정렬 여부와 관계없이 적용이 가능하고 단순하지만 데이터 수가 많을 경우 탐색 시 간이 오래 걸린다.
이진 탐색(Binary Search)
정렬된 데이터의 중간값을 기준으로 비교하여 탐색 범위를 절반씩 좁혀 가며 원하는 값을 갖는 방식이다. 데이터는 오름차순, 내림차순 등으로 정렬되어 있어야 하며, 빠른 탐색이 가능하다.
보간 탐색(Interpolation Search)
데이터값의 분포를 기반으로 하여 예상 위치를 수학적으로 계산한 뒤, 그 위치부터 탐색을 시작하는 방식이다. 데이터가 균등하게 분포된 정렬 배열에서는 이진 탐색보다 더 빠른 성능을 낼 수 있다.
트리 기반 탐색
트리 구조에서는 각 노드의 왼쪽에 작은 값을, 오른쪽에 큰 값을 저장하며, 자식 노드를 따라 이동하는 방식으로 탐색이 진행된다.
AVL 트리 기반 탐색
AVL 트리는 이진 탐색 트리의 한 종류로, 모든 노드에서 왼쪽과 오른쪽 서브 트리의 높이 차이가 1 이하가 되도록 유지한다.
트라이(Trie) 탐색
문자열의 접두사를 트리 형태로 표현해, 문자의 순서에 따라 노드를 따라가며 탐색을 수행한다. 문자열 검색에 특화되어 있어 접두사 기반 탐색에 매우 빠르다.
B 트리 / B+ 트리 탐색
균형 잡힌 트리 구조를 활용해, 디스크 기반 대용량 데이터에서 키 범위 탐색을 수 데이터베이스와 파일 시스템에서 널리 사용되며, 한 노드에 여러 키를 저장함으로써 디스크 접근 횟수를 줄일 수 있다.
탐색 알고리즘 선택 기준
박재영(2020)은 실제 업무 현장에서는 배열이나 리스트보다 해시테이블과 트리 구조가 데이터 검색과 관리에 더 효율적이라고 지적한다.
데이터 정렬
데이터가 정렬되어 있으면 이진 탐색이나 보간 탐색을 적용할 수 있다. 반대로 정렬 되지 않은 경우에는 선형 탐색처럼 단순한 방법이 필요하다.
데이터 구조
배열처럼 인덱스 접근이 가능한 자료구조에서는 이진 탐색을 적용할 수 있다. 하지만 연결 리스트는 인덱스 접근이 불가능하므로 순차 탐색이 적합하다.
데이터 특성
소규모 데이터에서는 단순한 알고리즘도 충분히 빠르지만, 대규모 데이터에서는 복잡도가 낮은 알고리즘을 선택해야 성능 문제가 줄어든다.
성능 및 리소스
빠른 응답이 필요한 시스템은 O(log n) 이하의 알고리즘을 적용하는 것이 바람직하다. 트리 기반 탐색이나 재귀 호출은 추가 메모리가 필요하므로, 메모리 제약이 있는 환경에서는 반복문 기반 탐색을 고려해야 한다.

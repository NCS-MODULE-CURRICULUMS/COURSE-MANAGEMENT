세 교과가 이어집니다. 화면 설계에서 무엇을 만들지 정했고, UI 디자인에서 그것을 남에게 넘길 수 있는 문서로 만들었습니다. 이 교과는 그 문서를 받아 실제로 열리는 쪽으로 옮깁니다.

UI 설계 확인하기
넘겨받은 설계를 읽고 구현에 옮길 수 있는 상태인지 확인하는 단계입니다. 화면과 폼의 흐름, 메뉴 구조, 내 · 외부 화면과 폼을 차례로 확인합니다. 이 단계에서 설계의 빈 곳을 찾아 두지 않으면 구현 도중에 멈추게 됩니다.
UI 구현하기
확인한 설계를 코드로 옮기는 단계입니다. 표준과 지침을 지켜 마크업하고, 접근성과 사용 편의를 고려해 흐름을 구현하고, 구현한 것을 테스트할 조건을 적습니다.

구현이라는 말 때문에 자바스크립트로 서버와 주고받는 일까지 떠올리기 쉽습니다. 이 교과의 범위는 거기까지 가지 않습니다. 화면이 스토리보드대로 보이고, 눌렀을 때 스토리보드대로 이동하면 됩니다.

실습 2 폴더를 «먼저» 만듭니다 — 나중에 옮기면 경로가 전부 깨집니다

목적 — 파일을 한군데 쏟아 놓고 만들다가 나중에 sub/ 로 옮기면 CSS 와 이미지 경로가 «전부» 깨집니다. 고치는 데 한 시간씩 걸립니다.

절차 1 — 구조를 먼저 만듭니다

index.html ← 조장 · 메인 css/ common.css ← 공용. 한 사람만 고칩니다 img/ logo.svg gym1.jpg sub/ facility.html ← 조원 1 reserve.html ← 조원 2 login.html ← 조원 3

파일 이름에 «한글과 빈칸» 을 쓰지 마십시오. 내 PC 에서는 열립니다. 서버에 올리면 안 열립니다. 시설 안내.html 이 아니라 facility.html 입니다. 영문 소문자와 - 만 쓰십시오.
절차 2 — 경로가 «어디서» 달라지는지 봅니다
어디서CSS 를 부르는 길
index.html (뿌리) href="css/common.css"
sub/facility.html href="../css/common.css" — ../ 가 붙습니다

../ 는 「한 칸 위로」 라는 뜻입니다. sub/ 안에서 보면 css/ 는 위로 한 번 올라가야 있습니다.

절차 3 — 경로를 «세어» 봅니다

눈으로는 안 보입니다. 파일이 정말 있는지 세어 주는 것을 만들어 두십시오.

# ../ 를 붙이고 sub/ 를 붙여 고친 뒤 python links.py site 쪽 3 · 경로 10건 · 깨진 것 0건

깨진 경로는 «화면에 안 보입니다». CSS 가 안 불러와지면 글자만 있는 하얀 쪽이 뜹니다. 「아직 꾸미기 전인가 보다」 하고 넘어가기 쉽습니다. 링크가 깨지면 눌러도 아무 일이 안 일어나거나 「파일을 찾을 수 없음」 이 뜹니다 — 채점 ③ 05 쪽 이동(10점)이 그대로 빕니다.

8그리드

칼럼 수와 간격을 스타일가이드에서 가져옵니다.

쓰이는 곳

채점 ① 06

도구

display:grid

12칼럼으로 잡는 이유

12는 2 · 3 · 4 · 6 으로 나누어떨어집니다. 한 줄을 둘로도, 셋으로도, 넷으로도 나눌 수 있어 대부분의 배치를 담을 수 있습니다. 스타일가이드에 다른 수가 적혀 있으면 그것을 따릅니다.

자주 걸리는 자리

감점 카드를 float 와 width:33% 로 만들어 간격이 들쭉날쭉

권함 display:grid 와 gap 을 씁니다. 간격이 한 값으로 정해집니다

간격 값도 스타일가이드에서 가져옵니다. 여백이 24px 로 적혀 있으면 gap: var(--gap) 로 씁니다.

해 보기 브라우저에서 F12 → 요소 검사로 카드 하나를 고르고, 오른쪽 Computed 에서 gap 값을 확인해 보십시오. 스타일가이드의 값과 같아야 합니다.
실습 8 숫자가 «딱 떨어지는지» 재 봅니다 — float 은 안 떨어집니다

목적 — 채점 ① 06 입니다. 칼럼 수와 간격을 스타일가이드에서 가져옵니다. 12 로 잡는 까닭은 2 · 3 · 4 · 6 으로 나누어떨어지기 때문입니다 — 한 줄을 둘로도 셋으로도 넷으로도 나눌 수 있습니다.

절차 1 — 그리드로 잡습니다

:root{ --gap: 24px; } .wrap { max-width: 1200px; margin: 0 auto; } .cards { display: grid; grid-template-columns: repeat(12, 1fr); gap: var(--gap); } .card { grid-column: span 4; } ← 12 ÷ 4 = 한 줄에 셋

절차 2 — 정말 그렇게 되는지 «잽니다»

브라우저에서 F12 → 요소 검사 로 카드를 고르고 Computed 에서 값을 봅니다.

안쪽 폭 : 1200 gap : 24px grid 폭 [384, 384, 384] 간격 [24, 24] → 384 × 3 + 24 × 2 = 1152 + 48 = 1200 ← 딱 떨어집니다

합이 안쪽 폭과 같은지 계산해 보십시오. 딱 떨어지면 제대로 잡힌 것입니다.

절차 3 — float 으로 만들면 어떻게 되는지 봅니다

.old .card{ float: left; width: 33%; } float 폭 [396, 396, 396] 간격 [0, 0] → 396 × 3 = 1188, 남는 12px, 카드끼리 «붙어» 있습니다

간격을 주려고 margin-right: 24px 를 넣으면 —

마진 24px 를 준 뒤 줄 수 : 2 ← 세 번째 카드가 «다음 줄로 떨어집니다» top : [64, 120] 폭 : [396, 396, 396] ← 폭은 그대로라 자리가 모자랍니다

이것이 float 의 함정입니다. 33% × 3 = 99% 라 간격 넣을 자리가 1% 뿐입니다. 간격을 주면 넘쳐서 줄이 바뀌고, 줄이 안 바뀌게 폭을 줄이면 이번엔 오른쪽이 빕니다. 「간격이 들쭉날쭉」 은 이렇게 생깁니다. gap 은 간격을 먼저 떼고 남은 것을 나누므로 이런 일이 없습니다.
감점권함
float 과 width:33% 로 만들어 간격이 들쭉날쭉 display:grid 와 gap. 간격이 한 값으로 정해집니다
절차 4 — 간격 값도 «가져옵니다»

스타일가이드에 여백이 24px 로 적혀 있으면 gap: var(--gap) 로 씁니다 (실습 3). 숫자를 직접 적지 마십시오 — 쪽마다 달라집니다.

절차 5 — 폭이 바뀔 때 몇 열이 되는지 적습니다

@media (max-width: 1199px){ .card{ grid-column: span 6; } } ← 2열 @media (max-width: 767px){ .card{ grid-column: span 12; } } ← 1열

스타일가이드에 적어 둔 열 수를 그대로 옮깁니다 (앞 교과 실습 8). 거기에 없으면 지금 정하고 되돌려 적으십시오 (실습 1).

안 될 때 볼 곳
이런 일이 생기면볼 곳
카드가 한 줄에 하나씩 grid-column 을 안 줬습니다. 기본은 1칸입니다
세 번째가 다음 줄로 span 합이 12 를 넘습니다. float 이면 절차 3
간격이 0 gap 이 없거나 var() 이름 오타입니다 (실습 3)
합이 안쪽 폭과 다름 padding 이 폭에 더해졌습니다. box-sizing: border-box 를 주십시오
가운데 정렬이 안 됨 .wrap 에 margin: 0 auto 가 있습니까

제출물 — 그리드 CSS + Computed 의 gap 화면 + 폭 · 간격을 잰 값과 합이 맞는 계산

스스로 확인 — ① 칼럼 수를 스타일가이드에서 가져왔습니까 ② gap 을 변수로 썼습니까 ③ 합이 딱 떨어집니까 ④ 폭이 바뀔 때 열 수를 적었습니까

9로고와 GNB 드롭다운

드롭다운은 마우스와 키보드 양쪽에서 열려야 합니다.

쓰이는 곳

채점 ① 02 · 03

한 줄 더

:focus-within

세 가지 상태

GNB 는 상태가 셋입니다. 지금 보고 있는 쪽을 표시하는 것까지가 채점 대상입니다.

로고

로고는 모든 쪽에서 같은 자리, 같은 크기여야 합니다. 그리고 누르면 메인페이지로 가야 합니다. 이것이 빠지는 조가 많습니다.

<h1 class="logo">
  <a href="/index.html">
    <img src="img/logo.svg" alt="공공 체육시설 예약">
  </a>
</h1>

이미지 로고에는 alt 에 서비스 이름을 적습니다. 「로고」 라고만 적으면 화면을 읽어 주는 기기에서 뜻이 전해지지 않습니다.

드롭다운 마크업

<li class="has-drop">
  <a href="reserve.html">예약</a>
  <ul class="drop">
    <li><a href="reserve.html">예약 신청</a></li>
    <li><a href="reserve.html#done">예약 완료</a></li>
  </ul>
</li>
.gnb li{ position:relative; }        기준점 — 이것이 없으면 드롭다운이 엉뚱한 곳에 뜸
.drop  { position:absolute; top:100%; left:0; display:none; }
.gnb li:hover > .drop,
.gnb li:focus-within > .drop{ display:block; }

position:relative 를 부모에 주는 것을 빠뜨리면 드롭다운이 쪽 맨 위로 올라가 버립니다. 가장 자주 나오는 실수입니다.

현재 쪽 표시의 모양

스타일가이드에 정해 둔 방식을 그대로 씁니다. 대개 셋 중 하나입니다.

  • 글자색을 주색으로 바꾸고 굵게
  • 아래에 밑줄 두 픽셀
  • 배경을 옅은 색으로

세 가지를 한꺼번에 쓰면 다른 항목과 견주어 지나치게 튑니다. 하나나 둘로 정합니다.

드롭다운을 :hover 로만 만들면 마우스 없이 열 수 없습니다. :focus-within 한 줄을 함께 적으면 탭 키로도 열립니다. 접근성을 보는 채점 묶음 ③ 에서 이 한 줄이 근거가 됩니다.
실습 9 기준점 한 줄을 빼면 드롭다운이 «쪽 맨 위» 로 갑니다 — 재 봤습니다

목적 — 채점 ① 02 · 03 입니다. 드롭다운은 마우스와 키보드 양쪽에서 열려야 합니다. 한 줄이 그 근거가 됩니다.

절차 1 — 로고를 만듭니다

<h1 class="logo"> <a href="index.html"> <img src="img/logo.svg" alt="공공 체육시설 예약"> </a> </h1>

빠뜨리기 쉬운 것
로고를 누르면 메인으로 이것이 빠지는 조가 많습니다. 모든 쪽에서 같은 자리 · 같은 크기여야 합니다
alt 에 서비스 이름 「로고」 라고만 적으면 읽어 주는 기기에서 뜻이 안 전해집니다
<h1> 으로 감싸기 실습 7 의 heading level of 1 안내가 같이 해결됩니다
절차 2 — 드롭다운을 만듭니다

<li class="has-drop"> <a href="reserve.html">예약</a> <ul class="drop"> <li><a href="reserve.html">예약 신청</a></li> </ul> </li>

.gnb li{ position: relative; } ← 기준점 .drop{ position: absolute; top: 100%; left: 0; display: none; } .gnb li:hover > .drop, .gnb li:focus-within > .drop{ display: block; }

절차 3 — 기준점을 빼고 «어디로 가는지» 잽니다

메뉴 항목 위치 left 47 · top 16 기준점 있을 때 드롭다운 left 47 · top 108 ← 메뉴 «바로 아래» 기준점 뺐을 때 드롭다운 left 0 · top 0 ← 쪽 맨 왼쪽 위

가장 자주 나오는 실수입니다. position:absolute 는 「어딘가를 기준으로」 띄운다는 뜻인데, 그 기준을 안 정해 주면 «쪽 전체» 를 기준으로 삼습니다. 그래서 top:100% 가 「메뉴 아래」 가 아니라 「쪽 맨 위」 가 됩니다. 부모에 position:relative 한 줄이면 끝납니다.
절차 4 — 탭 키로도 열리는지 «재 봅니다»

메뉴에 «포커스» 를 주기 «전» display: none 탭으로 포커스가 «간 뒤» display: block ← 열렸습니다 포커스가 «빠진 뒤» display: none ← 닫혔습니다

:hover 로만 만들면 «마우스 없이» 열 수 없습니다. :focus-within 한 줄을 함께 적으면 탭 키로도 열립니다. 접근성을 보는 채점 묶음 ③ 에서 이 한 줄이 근거가 됩니다. :focus 가 아니라 :focus-within 입니다 — :focus 는 자기 자신만, :focus-within 은 자기 «안»의 무엇이든 포커스를 받으면 걸립니다.
절차 5 — 세 상태를 갖춥니다
상태모양
①기본그냥 글자
②지금 보고 있는 쪽 class="on" + aria-current="page" (실습 5)
③하위 메뉴가 열린 모습 :hover · :focus-within

②의 모양은 스타일가이드에 정해 둔 것을 씁니다. 대개 셋 중 하나입니다.

· 글자색을 주색으로 바꾸고 굵게 · 아래에 밑줄 두 픽셀 · 배경을 옅은 색으로

세 가지를 한꺼번에 쓰면 지나치게 튑니다. 하나나 둘로 정하십시오.

안 될 때 볼 곳
이런 일이 생기면볼 곳
드롭다운이 쪽 맨 위에 뜸 position:relative 가 부모에 없습니다 — 절차 3
드롭다운이 항상 보임 display:none 을 안 줬습니다
마우스는 되는데 탭은 안 됨 :focus-within 이 없습니다 — 절차 4
탭이 메뉴로 안 감 항목이 <a> 가 아니라 <div> 입니다 (실습 10)
드롭다운이 잘림 부모에 overflow:hidden 이 있습니다
로고를 눌러도 안 감 <a href> 로 감쌌습니까 — 절차 1

제출물 — 로고 마크업 + 드롭다운 CSS + 기준점 있을 때 · 뺐을 때 화면 + 탭으로 열린 화면

스스로 확인 — ① 로고를 누르면 메인으로 갑니까 ② alt 에 서비스 이름이 있습니까 ③ 부모에 position:relative 가 있습니까 ④ 탭 키로 열립니까 ⑤ 세 상태가 다 있습니까

10버튼과 푸터

버튼은 세 상태, 푸터는 항목 배치를 봅니다.

쓰이는 곳

채점 ① 04 · 05

버튼 세 종류

스타일가이드에 정해 둔 버튼 종류를 그대로 만듭니다. 대개 주요 · 보조 · 비활성 셋입니다.

.btn      { background: var(--c-primary); color:#fff; }
.btn.gh   { background:#fff; color:var(--c-primary);
            border:1px solid var(--c-primary); }   보조
.btn.off  { background:#eee; color:#aaa;
            pointer-events:none; }                 비활성

비활성 버튼은 색만 흐리게 하는 것으로 끝내지 않습니다. 눌리지 않아야 합니다. 폼 안의 버튼이면 disabled 속성을 함께 씁니다.

a 로 만들 것과 button 으로 만들 것

보기에는 같아도 태그가 다릅니다. 기준은 눌렀을 때 쪽이 바뀌는가 입니다.

태그쓰는 자리예
<a>다른 쪽으로 갑니다 「예약하기」 「시설 목록」 「뒤로」
<button>그 쪽에서 무언가를 합니다 「시간대 선택」 「검색」 폼의 「제출」

<div class="btn"> 로 만들면 탭 키로 갈 수 없고 엔터로 눌리지도 않습니다. 검사에서는 걸리지 않지만 접근성을 보는 자리에서 불리합니다.

푸터

채점 항목 ① 04 가 「스타일 가이드에 맞게 푸터의 항목은 적절히 배치되어 있는가」 를 봅니다. 스타일가이드에 적어 둔 항목이 빠짐없이 들어가고 순서도 같아야 합니다.

항목내용
사업자 정보상호 · 주소 · 대표전화
약관 링크이용약관 · 개인정보처리방침 · 이메일무단수집거부
강조개인정보처리방침은 굵게 하는 것이 관례입니다

푸터도 common.css 에 두어 모든 쪽에서 같은 모양이 되게 합니다. 서브페이지의 푸터가 메인과 다르면 그 자리에서 감점됩니다.

실습 10 div 로 만든 버튼은 «탭이 안 닿습니다» — 재 봤습니다

목적 — 채점 ① 04 · 05 입니다. 버튼은 보기에 같아도 태그가 다르면 «되는 일» 이 다릅니다.

절차 1 — 넷을 나란히 만들어 «재 봅니다»

<button class="btn">진짜 버튼</button> <div class="btn">div 버튼</div> <a class="btn" href="#x">a 버튼</a> <button class="btn off" disabled>비활성</button>

tabIndex 탭이 닿는가 눌리는가 --------------- -------- ----------- -------- <button> 0 예 예 <div class="btn"> -1 «아니오» 예 <a href> 0 예 예 <button disabled> 0 아니오 «아니오»

div 의 tabIndex 가 «-1» 입니다. 탭 키로 갈 수 없다는 뜻입니다. 마우스를 못 쓰는 사용자는 그 버튼에 «닿을 수가» 없습니다. 검사에서는 안 걸립니다 (실습 7) — 그래서 통과했는데 접근성 자리에서 불리해집니다.
절차 2 — a 와 button 을 가릅니다

기준은 하나입니다 — 「눌렀을 때 쪽이 바뀌는가」

태그쓰는 자리예
<a>다른 쪽으로 갑니다 「예약하기」 · 「시설 목록」 · 「뒤로」
<button>그 쪽에서 무언가를 합니다 「시간대 선택」 · 「검색」 · 폼의 「제출」

보기에는 같게 만들어도 됩니다. .btn 하나를 a 와 button 에 같이 주면 모양은 같고 하는 일만 달라집니다.

절차 3 — 세 종류를 만듭니다

.btn { background: var(--primary); color:#fff; border:0; } .btn.gh { background:#fff; color:var(--primary); border:1px solid var(--primary); } ← 보조 .btn.off { background:#eee; color:#aaa; pointer-events:none; } ← 비활성

절차 4 — 비활성은 «색만» 으로 끝내지 않습니다

<div class="btn off"> pointer-events:none → 탭이 닿는가 아니오 → 스크립트로 부르면 «눌립니다» <button class="btn off" disabled> → 탭이 닿는가 아니오 → 눌리는가 «아니오» ← 진짜로 안 눌립니다

pointer-events:none 은 «마우스만» 막습니다. 보기에도 안 눌리는 것처럼 보이고 실제로 마우스로는 안 눌립니다. 그런데 그 요소가 「꺼진」 것은 아닙니다. 폼 안의 버튼이면 disabled 속성을 «함께» 쓰십시오. disabled 는 브라우저가 아예 안 보내 줍니다.
절차 5 — 푸터를 만듭니다 (① 04)

채점이 「스타일 가이드에 맞게 푸터의 항목은 적절히 배치되어 있는가」 를 봅니다. 빠짐없이 들어가고 «순서» 도 같아야 합니다.

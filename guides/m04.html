교과목

데이터베이스 구축

이 능력단위의 수행준거는 거의 모두 「업무 분석가가 …한 것을 확인할 수 있다」 로 끝납니다. 요구사항을 처음부터 만들어 내는 일이 아니라, 남이 정리해 온 것을 받아 그대로 만들 수 있는지 따져 보는 일입니다.

현행 시스템 분석하기
지금 돌아가고 있는 시스템이 무엇 위에 올라가 있는지 조사합니다. 운영체제 · DBMS · 미들웨어 · 언어 · 형상관리 · 망 구성입니다. 이것을 모르면 무엇을 바꿀 수 있고 무엇을 바꿀 수 없는지 판단할 수 없습니다.
요구사항 확인하기
더할 기능이 정말 그대로 만들 수 있는 것인지 따져 봅니다. 유스케이스로 옮겨 보면 빠진 것과 어긋난 것이 드러납니다.
분석모델 확인하기
기능이 실제로 어떤 순서로 돌아가는지(시퀀스), 그리고 어떤 통로로 주고받는지(API)를 정리합니다. 여기까지 나와야 개발자가 받아서 만들 수 있습니다.

1.1 현행 시스템 분석의 개념

학습 목표운행환경 조사 항목 일곱 가지를 설명할 수 있다.
자신의 PC 를 대상으로 조사를 수행하고 조사표를 작성할 수 있다.

현행 시스템 분석이란 새로운 기능을 추가하기에 앞서, 이미 운영 중인 시스템이 어떤 환경 위에서 동작하고 있는지를 조사하여 문서로 정리하는 작업을 말합니다. 운영체제, 데이터베이스, 개발 언어, 망 구성 등이 조사 대상입니다.

이 작업이 필요한 이유는 분명합니다. 기존 시스템의 환경을 알지 못하면 어떤 기능을 추가할 수 있고 어떤 기능은 추가할 수 없는지 판단할 수 없기 때문입니다. 비유하자면 이사를 앞두고 지금 사는 집의 구조를 먼저 확인하는 것과 같습니다. 방의 개수와 전기 용량을 알아야 어떤 가구를 옮길 수 있는지 정할 수 있습니다.

참고 — 이 능력단위의 수행준거는 「업무 분석가가 분석한 것을 확인할 수 있다」로 서술되어 있습니다. 요구사항을 새로 만들어 내는 작업이 아니라, 전달받은 내용이 구현 가능한지를 검토하는 작업입니다.

1.2 조사 항목

운행환경 조사표는 일곱 개 항목으로 구성됩니다. 이 일곱 줄이 채점 항목 ① 01 ~ 05 에 대응하며 배점은 25점입니다. 각 항목의 의미와 확인 방법은 다음 표와 같습니다. 확인 방법은 Windows 환경을 기준으로 정리하였습니다.

조사 항목의미 예확인 방법
운영체제
OS		 컴퓨터의 자원을 관리하고 응용 프로그램의 실행 환경을 제공하는 소프트웨어 Linux (CentOS 7) ⊞ + R 을 누른 뒤 winver 입력
데이터베이스
DBMS		 데이터를 저장하고 검색·변경할 수 있도록 관리하는 소프트웨어 MySQL 5.7 명령 프롬프트에서 mysql --version
미들웨어
WAS		 웹 요청을 받아 서블릿 등 프로그램을 실행하고 결과를 반환하는 서버 Apache Tomcat 8.5 브라우저에서 localhost:8080 접속
사용 언어 응용 프로그램을 작성한 언어. 프레임워크가 있으면 함께 적는다 Java 서블릿, JSP 기반 java -version
IDE 소스 코드를 작성하고 실행·디버깅하는 개발 도구 이클립스, 인텔리제이 설치된 프로그램 목록에서 확인
형상 관리 도구 소스 코드의 변경 이력을 기록하고 이전 상태로 되돌릴 수 있게 하는 도구 Git / GitHub git --version

용어 — WAS(Web Application Server)는 웹 서버와 달리 프로그램을 실행합니다. 포트는 하나의 컴퓨터에서 여러 프로그램을 구분하기 위한 번호이며, Tomcat 은 8080, MySQL 은 3306 을 기본값으로 사용합니다.

1.3 예시 ① — 내 PC 조사하기

학습 목표조사 항목 일곱 가지를 자신의 PC 에서 직접 확인할 수 있다.
확인한 값을 조사표의 형식에 맞추어 적을 수 있다.

낯선 서버로 들어가기 전에, 지금 쓰고 있는 컴퓨터를 먼저 조사해 봅니다. 조사 대상이 내 PC 일 뿐 절차는 서버와 완전히 같습니다. 명령을 쳐서 나온 값을 조사표로 옮기는 흐름을 여기서 익혀 두면, 뒤에서 원격 서버를 만나도 당황하지 않습니다.

Windows 에서는 명령 프롬프트를 씁니다. 키보드의 ⊞(윈도 키) 와 R 을 함께 누르면 작은 창이 열립니다. 거기에 cmd 라고 입력하고 Enter 를 누르면 검은 창이 나타납니다. 아래 실습의 명령은 모두 이 창에 입력합니다.

참고 — 명령을 입력할 때는 대소문자와 띄어쓰기를 그대로 따라 칩니다. java -version 에서 - 앞은 띄고 뒤는 붙입니다. 명령을 잘못 치면 'xxx'은(는) 내부 또는 외부 명령... 이라는 줄이 나옵니다. 이 줄이 나오면 오타이거나, 그 프로그램이 설치되어 있지 않다는 뜻입니다.
절차 1 — 운영체제 확인

ver 은 판 번호만 짧게 알려 주고, systeminfo 는 제품 이름까지 알려 줍니다. 두 개를 함께 씁니다. systeminfo 는 결과가 길어서, findstr 로 필요한 줄만 골라 냅니다.

참고 — 한글 Windows 에서는 OS Name 대신 「OS 이름」, OS Version 대신 「OS 버전」으로 나옵니다. 그때는 findstr /C:"OS 이름" /C:"OS 버전" 으로 바꾸어 칩니다. ⊞ + R 에 winver 를 입력해도 같은 내용을 창으로 볼 수 있습니다.
절차 2 — 사용 언어와 형상 관리 도구 확인

거의 모든 개발 도구는 --version 또는 -version 을 붙이면 자기 판을 알려 줍니다. 이 규칙 하나만 알면 처음 보는 도구도 조사할 수 있습니다.

주의 — java 만 -version(붙임표 하나)이고 나머지는 --version(붙임표 둘)입니다. 자바가 오래된 규칙을 쓰기 때문입니다. 설치되어 있지 않으면 오류 줄이 나오는데, 그것도 조사 결과입니다. 조사표에는 빈칸이 아니라 「없음」이라고 적습니다.
절차 3 — 망 구성 확인

ipconfig 는 이 PC 가 어떤 주소를 쓰고 있는지 알려 줍니다. 주소가 192.168. 이나 10. 으로 시작하면 내부망입니다. 내부망이면 밖에서 이 PC 로 바로 들어올 수 없습니다.

절차 4 — 조사표로 옮기기

확인한 값을 일곱 줄에 맞추어 적습니다. 내 PC 를 조사하면 대개 다음과 같은 모양이 됩니다. IDE 줄이 채워지는 것이 서버 조사와 다른 점입니다. 개발 도구는 서버가 아니라 개발자의 PC 에 설치되기 때문입니다.

조사 항목확인 방법 적은 값 (예)
운영체제ver · systeminfo Windows 11 Home 25H2 (빌드 26200), 64비트
데이터베이스mysql --version MySQL 8.0.44 (내 PC 는 도구와 서버가 같으므로 이 값이 맞습니다)
미들웨어설치 목록 확인 없음
사용 언어java -version 등 Java 21.0.2, Python 3.12.10, Node.js 24.11.1
IDE설치된 프로그램 목록 이클립스, Visual Studio Code
형상 관리 도구git --version Git 2.52.0
네트워크 환경ipconfig 내부망 192.168.0.0/24, 방화벽 없음
여기까지 명령을 쳐서 나온 값을 일곱 줄로 옮기는 것, 이것이 현행 시스템 분석의 전부입니다. 다음 절에서는 대상만 바뀝니다. 내 PC 가 아니라 남이 만들어 둔 서버입니다.

1.4 예시 ② — 원격 서버 한 대 조사하기

학습 목표원격 접속 도구로 서버에 접속할 수 있다.
조사 도구로 초안을 얻고, 항목마다 원래 명령으로 되짚어 확인할 수 있다.

실무에서 조사하는 대상은 내 PC 가 아니라 운영 중인 서버입니다. 서버는 대개 전산실에 있고 화면과 키보드가 붙어 있지 않습니다. 그래서 원격 접속으로 들어가 명령을 칩니다. 이 절에서는 강사가 올려 둔 서버 한 대(A팀 환경)를 함께 조사합니다.

접속 주소강사가 칠판에 적어 줍니다 (예시에서는 192.168.0.10) 접속 포트2201 계정survey 비밀번호강사가 안내합니다
주의 — 이 서버는 강의실 안쪽 망에서만 접속됩니다. 수업이 끝나면 강사가 내리므로 다음 시간에는 같은 주소로 접속되지 않습니다. 조사 결과와 근거 화면은 그날 안에 문서로 정리해 두어야 합니다.
이 서버는 강사가 어떻게 올리나 — 도커 코드 보기

훈련생은 읽지 않아도 됩니다. 조사 대상 서버가 어떻게 준비되는지 궁금할 때만 펴 보십시오. 아래 두 파일을 같은 폴더에 두고 그 폴더에서 docker compose up -d --build 를 실행하면 지금 조사할 서버 한 대가 올라옵니다.

여기서 올리는 것 — 서버 한 대(was-a)와 그 뒤의 데이터베이스 한 대입니다. 실습 1-1 의 네 환경은 이것과 다른 파일로 올립니다. 데이터베이스를 일부러 5.7 로 두었기 때문에, 접속 도구(8.0)와 판이 달라져 1.4.4 의 함정이 그대로 재현됩니다.
강사 참고 — 이 예시 서버와 실습 1-1 의 A팀은 같은 환경이고 포트도 둘 다 2201 이므로 동시에 띄울 수 없습니다. 두 가지 중 하나로 운영합니다. ① 예시를 이 파일로 올려 설명한 뒤 docker compose down 으로 내리고, 실습 1-1 의 네 환경을 올린다. ② 처음부터 네 환경만 올리고 예시도 A팀(2201)으로 진행한다. ②가 간단하며, 이 파일은 예시만 빠르게 보여 줄 때 씁니다.

docker-compose.yml — 서버 한 대와 데이터베이스 한 대의 정의.

# 예시 ② — 원격 서버 «한 대» 조사하기 (1.4절)
#
# 교안 1.4 의 화면을 그대로 재현하는 환경이다. 서버 한 대와 그 뒤의
# 데이터베이스 한 대만 올린다. 실습 1-1 의 네 환경과 달리 강사가 설명하며
# 함께 조사하는 용도이므로, 답이 교안에 이미 적혀 있다.
#
#   Ubuntu 22.04 · Apache Tomcat 8.5 · Java 8 · MySQL 5.7 · Git
#
# 쓰는 법 — 이 파일과 survey.sh 를 같은 폴더에 두고
#
#   docker compose up -d --build     환경을 올린다 (처음 한 번 오래 걸린다)
#   ipconfig                         나온 주소를 칠판에 적는다
#   docker compose down              수업이 끝나면 내린다
#
# 훈련생 접속 (강사 PC 주소가 192.168.0.10 인 경우)
#   ssh survey@192.168.0.10 -p 2201       계정 survey · 비밀번호 ncs2026
#
# 주의 — 수업용 설정이다. 비밀번호가 단순하므로 강의실 안쪽 망에서만 쓰고
#        수업이 끝나면 내린다. 인터넷에 포트를 열지 않는다.

name: ncs-example-one

services:

  # ── 조사 대상 서버 ──────────────────────────────────────────
  was:

      context: .

#!/bin/sh
# 운행환경 조사 도구 — 일곱 항목을 한 번에 훑는다.
#
# 손으로 하나씩 치면 빠뜨린다. 먼저 이것을 돌려 초안을 얻고,
# 그다음 항목마다 다시 확인해서 채운다. 초안을 그대로 내면 안 된다 —
# 이 도구가 「모름」 이나 「없음」 이라고 답하는 자리가 곧 직접 확인할 자리다.
#
#   survey
#
# 어떤 환경에서도 돌아가도록 설치되지 않은 명령은 건너뛴다.

have() { command -v "$1" >/dev/null 2>&1; }
row()  { printf '%s%s\n' "$1" "$2"; }

echo "===== 운행환경 조사 : $(hostname) : $(date '+%Y-%m-%d %H:%M') ====="

# 1. 운영체제
if [ -r /etc/os-release ]; then
    . /etc/os-release
    row "운영체제      " "${PRETTY_NAME:-$NAME $VERSION_ID}"
else
    row "운영체제      " "$(uname -sr)"
fi

# 2. 데이터베이스 — 이 서버에 깔린 «접속 도구» 를 찾는다.
#    접속 도구와 DB 서버는 다른 프로그램이고 판도 다르다.
#    서버의 판은 서버에 직접 물어봐야 하며 여기서는 알 수 없다.
db="없음"
if have psql; then
    db="접속 도구 psql $(psql --version 2>/dev/null | awk '{print $3}')"
elif have mysql; then
    db="접속 도구 $(mysql --version 2>/dev/null | tr -d , | awk '{print $1, $2, $3, $4, $5}')"
elif have mariadb; then
    db="접속 도구 $(mariadb --version 2>/dev/null | tr -d , | awk '{print $1, $2, $3, $4, $5}')"
fi
row "데이터베이스  " "$db"
row "              " "  ↳ 서버의 판은 DB 서버에 직접 물어볼 것 (도구 판과 다르다)"

# 3. 미들웨어 — 무엇이 웹 요청을 받는가
mw="모름 — 직접 확인할 것"
if [ -x /usr/local/tomcat/bin/version.sh ]; then
    mw="$(/usr/local/tomcat/bin/version.sh 2>/dev/null | sed -n 's/^Server version: *//p')"
fi
have httpd    && mw="$(httpd -v 2>/dev/null | sed -n 's/^Server version: *//p')"
have apache2  && mw="$(apache2 -v 2>/dev/null | sed -n 's/^Server version: *//p')"
have nginx    && mw="$(nginx -v 2>&1 | sed 's|.*nginx/|nginx |')"
have gunicorn && mw="Gunicorn $(gunicorn --version 2>/dev/null | tr -d '()' | awk '{print $NF}')"
row "미들웨어      " "$mw"

# 4. 사용 언어
lang=""
have java    && lang="$lang Java $(java -version 2>&1 | sed -n '1s/.*"\(.*\)".*/\1/p');"
have python3 && lang="$lang Python $(python3 --version 2>&1 | awk '{print $2}');"
have php     && lang="$lang PHP $(php -v 2>/dev/null | sed -n '1s/^PHP \([0-9.]*\).*/\1/p');"
have node    && lang="$lang Node.js $(node --version 2>/dev/null);"
[ -z "$lang" ] && lang=" 모름 — 직접 확인할 것"
row "사용 언어     " "$(echo "$lang" | sed 's/^ //; s/;$//')"

# 5. IDE — 서버에는 없는 것이 정상이다
row "IDE           " "서버에 없음 — 개발 PC 에서 확인할 것"

# 6. 형상 관리 도구
scm="없음"
have git && scm="Git $(git --version 2>/dev/null | awk '{print $3}')"
have svn && scm="Subversion $(svn --version --quiet 2>/dev/null)"
row "형상관리      " "$scm"

# 7. 네트워크 환경
row "네트워크      " "주소 $(hostname -i 2>/dev/null || echo 모름)"
if have ss; then
    ports=$(ss -ltn 2>/dev/null | awk 'NR>1 && $4 !~ /127.0.0.11/{print $4}' | sed 's/.*://' | sort -un | tr '\n' ' ')
    row "              " "  열린 포트 $ports"
fi

echo "====================================================="
echo "「모름」 과 「없음」 이 적힌 줄은 직접 확인해서 채울 것."
주의 — survey.sh 를 옮겨 적을 때는 줄 끝을 LF 로 두어야 합니다. Windows 편집기에서 CRLF 로 저장하면 컨테이너 안에서 no such file or directory 가 나며 실행되지 않습니다. VS Code 오른쪽 아래의 CRLF 를 눌러 LF 로 바꿉니다.
1.4.1 접속하기

두 가지 방법이 있습니다. 설치가 필요 없는 첫 번째 방법을 권합니다.

방법 1 — Windows 기본 ssh
Windows 10 · 11 에는 원격 접속 도구가 기본으로 들어 있습니다. 명령 프롬프트에 다음과 같이 입력합니다. -p 뒤의 숫자가 팀마다 다른 포트입니다.

ssh survey@192.168.0.10 -p 2201

처음 접속하면 The authenticity of host ... can't be established. 라는 물음이 나옵니다. 「이 서버가 처음 보는 서버인데 계속할까요」 라는 뜻입니다. yes 를 입력하고 Enter 를 누릅니다. 두 번째부터는 나오지 않습니다.

그다음 비밀번호를 묻습니다. 입력해도 화면에 아무것도 나타나지 않습니다. 지워진 것이 아니라 보안을 위해 감추는 것이므로, 그대로 끝까지 치고 Enter 를 누릅니다.

접속이 되면 줄 맨 앞이 C:\Users\hong> 에서 survey@was-a:~$ 로 바뀝니다. 이 줄이 바뀌었다는 것이 「지금부터 치는 명령은 내 PC 가 아니라 서버에서 돌아간다」 는 표시입니다.

방법 2 — PuTTY
PuTTY 를 쓰는 경우에는 아래 창에서 세 군데를 채우고 Open 을 누릅니다.

칸입력할 값설명
Host Name192.168.0.10 강사가 알려 준 주소
Port2201 팀마다 다릅니다. 기본값 22 를 지우고 넣습니다
Connection typeSSH 기본값입니다. 바뀌어 있으면 SSH 로 되돌립니다

검은 창이 열리면 login as: 에 survey 를 입력하고, 이어서 비밀번호를 입력합니다. 이 또한 화면에 나타나지 않습니다.

접속이 되지 않을 때 — 세 가지가 대부분입니다. 오류 문구를 보고 어느 경우인지 가려 냅니다.

1.4.2 조사 도구를 먼저 돌린다

접속했다고 해서 곧바로 일곱 항목을 하나씩 치기 시작하면 안 됩니다. 실무에서도 그렇게 하지 않습니다. 이유는 두 가지입니다.

  1. 빠뜨립니다. 일곱 항목을 기억에 의존해 치다 보면 한두 줄이 빈 채로 넘어갑니다. 빈칸은 그대로 감점입니다.
  2. 시간이 모자랍니다. 서버가 한 대면 손으로 해도 되지만, 실무에서는 수십 대를 조사합니다. 손으로는 끝나지 않습니다.

그래서 먼저 한 번에 훑는 도구를 돌려 초안을 얻고, 그다음 항목마다 되짚어 확인합니다. 이 서버에는 survey 라는 조사 도구가 미리 설치되어 있습니다. 접속한 창에 다음과 같이 입력합니다.

survey

중요 — 이 화면을 그대로 옮겨 적으면 안 됩니다. 도구는 초안을 만들어 줄 뿐입니다. 도구가 「모름」 · 「없음」 · 「접속 도구」 라고 답한 자리가 곧 직접 확인해야 할 자리입니다.

도구가 스스로 끝내지 못하는 자리는 다음 셋입니다. 왜 그런지 알아 두어야 다른 현장에서도 같은 판단을 할 수 있습니다.

도구의 답왜 도구가 끝내지 못하는가 사람이 할 일
데이터베이스
「접속 도구 …」		 이 서버에 있는 것은 접속 도구뿐이다. 데이터베이스 서버는 다른 컴퓨터에서 돌고 있다 DB 서버에 직접 물어본다 (1.4.4)

1.4.3 항목별로 되짚어 확인하기

초안이 맞는지 항목마다 원래 명령으로 다시 확인합니다. 도구가 어디에서 그 값을 가져왔는지 알게 되므로, 조사 도구가 없는 서버를 만나도 혼자 조사할 수 있습니다.

조사 항목서버에서 치는 명령 읽는 법
운영체제cat /etc/os-release 리눅스는 이 파일에 자기 정보를 적어 둔다. PRETTY_NAME 줄을 쓴다
미들웨어/usr/local/tomcat/bin/version.sh Server version 줄. 제품 이름과 판이 함께 나온다
사용 언어java -version 1.8.0 이 곧 Java 8 이다
형상 관리git --version · svn --version 둘 다 없으면 「없음」. 그것이 곧 문제점이 된다
네트워크hostname -i · ss -ltn ss 는 열려 있는 포트 목록이다. 22 는 원격 접속, 8080 은 웹이다
용어 — 포트는 한 대의 컴퓨터에서 여러 프로그램을 구분하는 번호입니다. 건물은 하나인데 호실 번호가 다른 것과 같습니다. 22 는 원격 접속, 80 과 8080 은 웹, 3306 은 MySQL 이 주로 씁니다. ss 결과에 127.0.0.11 이 보이면 그것은 실습 환경이 내부에서 쓰는 주소이므로 조사 대상이 아닙니다.
1.4.4 데이터베이스 — 도구의 판과 서버의 판

일곱 항목 가운데 가장 많이 틀리는 곳입니다. 먼저 흔히 하는 대로 해 보고, 왜 틀리는지 확인합니다.

mysql --version 이 알려 주는 8.0 은 이 서버에 깔린 접속 도구의 판입니다. 우리가 조사표에 적어야 할 것은 데이터를 실제로 보관하고 있는 데이터베이스 서버의 판, 곧 5.7 입니다.

전화기와 상대방의 차이입니다. 내 전화기가 최신이라고 해서 상대방의 전화기도 최신인 것은 아닙니다. 판을 알려면 상대방에게 물어봐야 합니다.

서버에 직접 물어보는 명령은 데이터베이스 종류마다 다릅니다. -h 뒤가 데이터베이스 서버의 이름입니다.

데이터베이스서버에 직접 물어보는 명령
MySQL mysqladmin -h db-a -uroot -p version
MariaDB mariadb --skip-ssl -h db-c -uroot -p -e "select version();"
PostgreSQL psql -h db-b -U postgres -c "select version();"
주의 — 최신 MariaDB 접속 도구는 암호화 연결을 기본으로 요구하므로, 오래된 서버에 붙으면 TLS/SSL error: SSL is required 라는 줄이 나옵니다. 이때 --skip-ssl 을 붙입니다. 이것 자체가 조사 결과입니다 — 「현행 DB 서버가 오래되어 암호화 연결을 지원하지 않음」은 뒤에서 문제점으로 적을 거리가 됩니다.

절차 1. 접속하고 서버 이름 확인
ssh survey@<주소> -p <팀 포트> 로 접속합니다. 들어가면 hostname 을 쳐서 어느 서버에 들어왔는지 먼저 확인합니다. 이 이름을 조사표 맨 위에 적습니다.

절차 2. 조사 도구를 먼저 돌린다
survey 를 입력해 초안을 얻습니다. 이 화면을 캡처해 근거_01_조사도구.png 로 저장합니다. 이 초안을 그대로 제출하지 않습니다.

절차 3. 도구의 답을 세 무리로 나눈다
초안을 보고 다음과 같이 표시합니다. 무엇을 더 해야 하는지가 여기서 정해집니다.

  1. 판까지 나온 줄 — 절차 4 에서 원래 명령으로 되짚기만 하면 됩니다.
  2. 「접속 도구」라고 나온 줄 — 절차 5 에서 서버에 직접 물어봐야 합니다.
  3. 「모름」 · 「없음」 · 「서버에 없음」인 줄 — 절차 6 에서 사람에게 묻거나 없다고 확정해야 합니다.

절차 4. 항목별로 되짚어 확인
1.4.3 의 명령을 씁니다. 다만 미들웨어는 팀마다 프로그램이 다르므로 아래에서 자기 환경에 맞는 것을 찾아 칩니다. survey 가 알려 준 프로그램 이름을 보고 고르면 됩니다.

초안에 나온 이름판을 확인하는 명령
Apache Tomcat/usr/local/tomcat/bin/version.sh
Apache/2.xapache2 -v
nginxnginx -v
Gunicorngunicorn --version

사용 언어와 형상 관리 도구도 마찬가지입니다. java -version 이 듣지 않으면 python3 --version · php -v · node --version 을, git --version 이 듣지 않으면 svn --version 을 쳐 봅니다.

없는 명령을 쳤을 때 — command not found 가 나옵니다. 잘못한 것이 아닙니다. 「이 서버에는 그것이 없다」는 조사 결과를 얻은 것입니다. 형상 관리 도구가 Git 도 Subversion 도 없다면 조사표에 「없음」이라고 적고, 그것을 문제점으로 적어 둡니다.

절차 5. 데이터베이스 서버에 직접 물어보기
1.4.4 의 표에서 자기 환경에 맞는 명령을 골라 칩니다. -h 뒤에는 위 배정표의 DB 서버 이름을 넣습니다. 비밀번호는 강사가 안내합니다. 결과 화면을 근거_02_DB서버판.png 로 저장합니다.

여기서 초안과 값이 달라지면 제대로 한 것입니다. 달라지지 않았다면 접속 도구의 판을 그대로 본 것은 아닌지 다시 확인하십시오.

절차 6. 사람에게 물어야 하는 줄 처리
IDE 는 서버에 없습니다. 「개발 PC 에서 확인 필요」라고 적거나, 강사에게 물어 답을 받습니다. 네트워크 환경은 hostname -i 와 ss -ltn 으로 주소와 열린 포트까지 적고, 방화벽·IDS 는 「확인 필요」 또는 「없음」으로 적습니다.

절차 7. 접속 끊기
exit 를 입력합니다.

절차 8. 조사표 작성
1.5 의 서식에 맞추어 일곱 줄을 채웁니다. 일곱 줄 모두 판(버전)이 적혀 있는지 마지막으로 확인합니다.

제출물 — 팀 환경 운행환경 조사표 1부(일곱 줄) + 근거 화면 2장 이상

스스로 확인 — 다음 셋을 말할 수 있으면 끝난 것입니다. ① 일곱 줄에 모두 값과 판이 있는가 ② 데이터베이스 줄이 서버가 답한 값인가 ③ 각 줄의 값이 어느 명령에서 나왔는지 말할 수 있는가

발표 때 비교할 것 — 네 팀의 조사표를 나란히 놓으면 같은 「웹 시스템」인데도 운영체제 · 미들웨어 · 언어 · 데이터베이스 · 형상 관리 도구가 모두 다릅니다. 그래서 조사를 먼저 하는 것입니다. 조사 없이 「웹이니까 자바겠지」라고 짐작하면 그 뒤의 설계가 전부 어긋납니다.
현업에서는 — 조사표 서식은 발주기관이 지정하므로 프로젝트마다 다릅니다. 반면 수집 방법은 대체로 같습니다. 서버에 원격으로 들어가 cat /etc/os-release, java -version 처럼 직접 확인하는 것이 기본이고, 오늘 쓴 survey 처럼 한 번에 훑는 스크립트를 먼저 돌리는 것도 실제로 하는 방식입니다. 서버가 수십 대를 넘어가면 Ansible 같은 도구로 한 번에 모으고, 조직 차원에서는 CMDB(구성관리 데이터베이스)에 등록해 계속 갱신합니다. 상용은 ServiceNow, 공개 도구로는 GLPI · Snipe-IT 가 있습니다.

# 원격 조사 실습용 «현행 시스템» 서버
#
# 훈련생 PC 에는 아무것도 깔지 않는다. 강사 PC 에서 이 서버들을 올려 두면
# 훈련생은 Windows 에 기본으로 들어 있는 ssh 나 PuTTY 로 들어와 조사한다.
#
# 바탕 이미지는 아직 지원되는 것으로 고른다 — 지원이 끝난 배포판은
# apt 저장소가 사라져 패키지를 받을 수 없다(Debian 11 에서 겪었다).
#
# 팀마다 다른 환경을 주기 위해 BASE · EXTRA · START 를 밖에서 넣는다.
ARG BASE=tomcat:8.5-jdk8-temurin-jammy
FROM ${BASE}

ARG EXTRA=""
ARG PIP=""
ARG START="true"
ENV START=${START}

RUN apt-get update \
 && apt-get install -y --no-install-recommends \
      openssh-server procps iproute2 net-tools less ${EXTRA} \
 && rm -rf /var/lib/apt/lists/* \
 && mkdir -p /run/sshd \
 && useradd -m -s /bin/bash survey \
 && echo 'survey:ncs2026' | chpasswd \
 && sed -i 's/^#\?PermitRootLogin.*/PermitRootLogin no/' /etc/ssh/sshd_config \
 && sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication yes/' /etc/ssh/sshd_config

# 파이썬 환경에서만 쓰는 것 (예: gunicorn)
RUN if [ -n "$PIP" ]; then pip install --no-cache-dir $PIP; fi

# 조사 도구 — 훈련생이 맨 먼저 돌린다
COPY survey.sh /usr/local/bin/survey
RUN chmod +x /usr/local/bin/survey

EXPOSE 22

# 응용 서버를 뒤로 띄우고 ssh 를 앞에서 돌린다
CMD ["/bin/sh", "-c", "$START >/tmp/app.log 2>&1 & exec /usr/sbin/sshd -D -e"]

survey.sh — 훈련생이 접속해서 맨 먼저 돌리는 조사 도구.

#!/bin/sh
# 운행환경 조사 도구 — 일곱 항목을 한 번에 훑는다.
#
# 손으로 하나씩 치면 빠뜨린다. 먼저 이것을 돌려 초안을 얻고,
# 그다음 항목마다 다시 확인해서 채운다. 초안을 그대로 내면 안 된다 —
# 이 도구가 「모름」 이나 「없음」 이라고 답하는 자리가 곧 직접 확인할 자리다.
#
#   survey
#
# 어떤 환경에서도 돌아가도록 설치되지 않은 명령은 건너뛴다.

have() { command -v "$1" >/dev/null 2>&1; }
row()  { printf '%s%s\n' "$1" "$2"; }

echo "===== 운행환경 조사 : $(hostname) : $(date '+%Y-%m-%d %H:%M') ====="

# 1. 운영체제
if [ -r /etc/os-release ]; then
    . /etc/os-release
    row "운영체제      " "${PRETTY_NAME:-$NAME $VERSION_ID}"
else
    row "운영체제      " "$(uname -sr)"
fi

# 2. 데이터베이스 — 이 서버에 깔린 «접속 도구» 를 찾는다.
#    접속 도구와 DB 서버는 다른 프로그램이고 판도 다르다.
#    서버의 판은 서버에 직접 물어봐야 하며 여기서는 알 수 없다.
db="없음"
if have psql; then
    db="접속 도구 psql $(psql --version 2>/dev/null | awk '{print $3}')"
elif have mysql; then
    db="접속 도구 $(mysql --version 2>/dev/null | tr -d , | awk '{print $1, $2, $3, $4, $5}')"
elif have mariadb; then
    db="접속 도구 $(mariadb --version 2>/dev/null | tr -d , | awk '{print $1, $2, $3, $4, $5}')"
fi
row "데이터베이스  " "$db"
row "              " "  ↳ 서버의 판은 DB 서버에 직접 물어볼 것 (도구 판과 다르다)"

# 3. 미들웨어 — 무엇이 웹 요청을 받는가
mw="모름 — 직접 확인할 것"
if [ -x /usr/local/tomcat/bin/version.sh ]; then
    mw="$(/usr/local/tomcat/bin/version.sh 2>/dev/null | sed -n 's/^Server version: *//p')"
fi
have httpd    && mw="$(httpd -v 2>/dev/null | sed -n 's/^Server version: *//p')"
have apache2  && mw="$(apache2 -v 2>/dev/null | sed -n 's/^Server version: *//p')"
have nginx    && mw="$(nginx -v 2>&1 | sed 's|.*nginx/|nginx |')"
have gunicorn && mw="Gunicorn $(gunicorn --version 2>/dev/null | tr -d '()' | awk '{print $NF}')"
row "미들웨어      " "$mw"

# 4. 사용 언어
lang=""
have java    && lang="$lang Java $(java -version 2>&1 | sed -n '1s/.*"\(.*\)".*/\1/p');"
have python3 && lang="$lang Python $(python3 --version 2>&1 | awk '{print $2}');"
have php     && lang="$lang PHP $(php -v 2>/dev/null | sed -n '1s/^PHP \([0-9.]*\).*/\1/p');"
have node    && lang="$lang Node.js $(node --version 2>/dev/null);"
[ -z "$lang" ] && lang=" 모름 — 직접 확인할 것"
row "사용 언어     " "$(echo "$lang" | sed 's/^ //; s/;$//')"

# 5. IDE — 서버에는 없는 것이 정상이다
row "IDE           " "서버에 없음 — 개발 PC 에서 확인할 것"

# 6. 형상 관리 도구
scm="없음"
have git && scm="Git $(git --version 2>/dev/null | awk '{print $3}')"
have svn && scm="Subversion $(svn --version --quiet 2>/dev/null)"
row "형상관리      " "$scm"

# 7. 네트워크 환경
row "네트워크      " "주소 $(hostname -i 2>/dev/null || echo 모름)"
if have ss; then
    ports=$(ss -ltn 2>/dev/null | awk 'NR>1 && $4 !~ /127.0.0.11/{print $4}' | sed 's/.*://' | sort -un | tr '\n' ' ')
    row "              " "  열린 포트 $ports"
fi

echo "====================================================="
echo "「모름」 과 「없음」 이 적힌 줄은 직접 확인해서 채울 것."

해 보기 목표 시스템 표를 다 쓴 뒤 요구사항 두 줄을 다시 읽어 보십시오. 요구사항을 만들기 위해 필요한 것이 목표 시스템에 빠짐없이 들어 있어야 합니다. 인증을 더한다면 인증을 무엇으로 할지가 표에 있어야 합니다.

순서가 중요합니다 — 요구사항을 먼저 받습니다

목표 시스템은 현행 시스템만 보고 정할 수 없습니다. 「MySQL 5.7 은 오래됐으니 8.0 으로 올린다」는 이유가 되지 않습니다. 무엇을 더 해 달라고 했는지를 받아 본 다음에야 지금 것으로 되는지 안 되는지 따질 수 있습니다.

현행 조사 (st2) → 문제점과 요구사항 (st3) → 목표 시스템 (지금)

그래서 이 단계에서 할 일은 하나입니다. 요구사항을 하나씩 들고 가서 현행 시스템에 대 보는 것입니다. 대 보아 들어가면 그대로 두고, 들어가지 않으면 그때 바꿉니다.

두 경우를 나란히 놓고 보십시오 — 현행 시스템은 똑같습니다. MySQL 5.7 도 그대로이고 Java 8 도 그대로입니다. 그런데 ㄱ 에서는 「유지」, ㄴ 에서는 「전환」이 답입니다. 결정을 가른 것은 현행이 아니라 요구사항입니다. 그래서 요구사항을 먼저 받아야 하고, 이유 칸에 요구사항이 등장해야 합니다.
이유로 쓰면 안 되는 말 — 「최신이라서」 · 「요즘 많이 써서」 · 「성능이 좋아서」는 이유가 아닙니다. 앞의 요구사항과 이어지지 않기 때문입니다. 어느 요구사항이 안 들어가서 바꾸는지를 적습니다.

절차 4. 확인해 보고 넘어간다
「안 된다」고 적으려면 정말 안 되는지 확인해 보아야 합니다. 1절에서 접속한 서버에서 직접 쳐 볼 수 있습니다.

mysql -h db-a -uroot -p -e "SELECT RANK() OVER (ORDER BY id) FROM books;"

ERROR 1064 라는 문법 오류가 납니다. 문법을 틀려서가 아니라 이 판이 그 문법을 모르기 때문입니다. 반면 SELECT JSON_OBJECT('a',1); 은 됩니다 — JSON 은 5.7 에 이미 들어와 있습니다. 「옛날 판이니 다 안 될 것」이라고 넘겨짚지 말고 이렇게 하나씩 확인합니다.

절차 5. 기대 효과를 적는다
기대 효과는 문제점이 사라진 모습입니다. 문제점 1 이 「누구나 삭제할 수 있음」이었다면 기대 효과는 「권한 있는 사람만 도서를 관리하게 되어 자료가 지켜짐」입니다.

판이 다르면 여기서 갈립니다

같은 SQL 을 두 판에 던져 보면 목표 시스템을 정할 근거가 바로 나옵니다.

mysql> SELECT VERSION(); 5.7.44 mysql> SELECT RANK() OVER (ORDER BY id) FROM books; ERROR 1064 (42000): You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version for the right syntax to use near '(ORDER BY id) FROM books' at line 1

같은 문장을 8.0 에 던지면 이렇게 됩니다.

+------+-----+ | id | rnk | +------+-----+ | 1 | 1 | | 2 | 2 | +------+-----+

「문법 오류」 라고 나오지만 문법이 틀린 것이 아닙니다. 5.7 이 윈도 함수를 아예 모르기 때문에 그 자리를 못 읽는 것입니다. 판을 올려야 하는 요구사항은 이렇게 «돌려 보고» 적습니다 — 「5.7 에서 ERROR 1064」 가 곧 근거입니다.

절차 5 — 액터와 유스케이스를 선으로 잇습니다

액터와 유스케이스를 잇는 선에는 화살표가 없습니다. 「누가 이 기능을 쓴다」는 연결이지 방향이 있는 흐름이 아니기 때문입니다. 화살표가 붙어 있으면 ② 08 에서 걸립니다.

여기서 가장 많이 틀립니다 — «include» 와 «extend» 는 선 모양이 똑같고 방향만 다릅니다. 가리는 방법은 「없으면 안 되는가」입니다. 없으면 안 되면 include(대여에는 인증이 반드시 필요), 있어도 되고 없어도 되면 extend(대여 연장은 원할 때만).
«extend» 는 이번 산출물에 쓸 자리가 없습니다 — 받은 요구사항이 인증 추가와 대여 추가 둘뿐이고, 그 안에 「조건일 때만 붙는 기능」이 없기 때문입니다. 위 표의 대여 연장은 뜻을 보이기 위한 예일 뿐, 요구사항에 없으므로 그림에 그리면 안 됩니다. 조사에 없는 것을 그리면 채점 항목 ② 10 에서 걸립니다. extend 는 「알아 두는 것」이고, 이번에 「쓰는 것」은 include 하나입니다.
일반화도 이번 산출물에 꼭 넣지 않아도 됩니다 — 회원은 비회원이 하는 도서 조회를 그대로 하므로 회원 ──▷ 비회원 으로 묶으면 선이 하나 줄어듭니다. 다만 위 완성 그림처럼 각각 선을 그어도 틀린 것이 아닙니다. 채점 항목 ② 08 은 쓴 표기가 올바른지를 보지 일반화를 썼는지를 보지 않습니다. 자신 없으면 쓰지 마십시오. 잘못 쓰면 감점이지만 안 써서 감점되지는 않습니다.
삼각형은 «속이 비어» 있어야 합니다 — 까맣게 칠하면 다른 뜻(합성)이 됩니다. draw.io 에서는 선을 고르고 [서식] → [화살표 끝] → [블록 · 채우지 않음] 입니다.
절차 6 — 공통 동작을 «include» 로 묶습니다
목록에 없던 「인증 확인」이 왜 나오나 — 실습 2-6 의 유스케이스 목록은 일곱 개였습니다. 그런데 대여 요청도 반납 처리도 먼저 로그인했는지 확인해야 합니다. 같은 일이 여러 곳에서 되풀이되면 하나로 빼내어 «include» 로 잇습니다. 그리면서 알게 되는 것이며, 이것이 그림을 그리는 이유이기도 합니다.
  1. 인증 확인 타원을 하나 더 놓습니다 (점선).
  2. 대여 요청 → 인증 확인 으로 선을 긋습니다. 부르는 쪽에서 불리는 쪽으로 향합니다.
  3. 선을 고르고 [선 스타일] → 점선, [화살표 끝] → 열린 화살표 로 바꿉니다.
  4. 선을 두 번 눌러 «include» 라고 적습니다. («» 는 ㄴ 을 누르고 한자 키를 누르면 나옵니다.)

회원가입 · 로그인 · 대여 요청 — 세 건이면 충분합니다

절차 2 — 네 칸으로 적습니다
칸무엇을 적나예
헤더본문과 별개로 딸려 가는 정보
주로 「나 누구다」		 Authorization: Bearer <token>
요청보내는 값{ "bookId": 128 }
응답성공했을 때 받는 값 { "rentalId": 4021, "status": "PENDING" }
상태 코드성공 하나 + 실패 한둘 201 · 401 · 409
중괄호가 낯설다면 — { "bookId": 128 } 은 「bookId 라는 이름의 값이 128 이다」라는 뜻입니다. 이름은 큰따옴표로 감싸고, 이름과 값 사이에 쌍점을 찍습니다. 값이 글자면 값에도 따옴표를 붙이고("PENDING"), 숫자면 붙이지 않습니다(128). 여럿이면 쉼표로 잇습니다. 이 네 가지가 전부입니다.
절차 3 — 상태 코드를 «검증 기준» 에서 끌어옵니다

외워서 고르지 않습니다. 실습 2-5 에 이미 적어 두었습니다.

고르는 요령은 거절하는 이유를 보는 것입니다.

거절하는 이유코드이 시스템의 예
보낸 값이 잘못됐다400제목 없이 도서 등록
로그인을 안 했다401로그아웃 상태로 대여 신청
권한이 없다403회원이 대여 승인을 시도
그런 것이 없다404없는 도서 번호

401 과 403 을 헷갈립니다 — 401 은 「누구인지 모르겠다」(로그인 자체를 안 함), 403 은 「누군지는 알겠는데 그럴 자격이 없다」(회원이 관리자 일을 하려 함)입니다.
절차 4 — 실패했을 때 무엇이 오는지도 적습니다

코드만 적고 끝내지 않습니다. 화면에 띄울 말까지 적어야 개발자가 그대로 만들 수 있습니다 (채점 ③ 20).

"401": { "message": "로그인이 필요합니다" } "409": { "message": "이미 대여 중인 도서입니다" }

이 말은 어디서 오나 — 실습 2-8 의 예외 흐름입니다. 「2b. 이미 대여 중인 경우 — 『이미 대여 중인 도서입니다』를 띄우고 끝낸다」 라고 적어 두었다면, 그 따옴표 안의 말을 그대로 옮기면 됩니다.
절차 5 — 세 건을 마저 씁니다

회원가입과 로그인도 같은 네 칸으로 씁니다. 코드만 달라집니다.

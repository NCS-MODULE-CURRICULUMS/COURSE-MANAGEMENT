PATH 가 무엇인가

mysql 이라고 치면 윈도는 그 이름의 실행 파일을 정해진 폴더 목록에서 찾습니다. 그 목록이 PATH 입니다. MySQL 의 bin 폴더가 목록에 없으면 그 폴더로 직접 들어가야만 명령이 돕니다.

등록한 뒤에도 되지 않으면 대부분 명령 프롬프트를 다시 열지 않아서입니다. PATH 는 창이 열릴 때 한 번 읽히므로, 이미 열려 있던 창에는 반영되지 않습니다.

해 보기 등록하기 전에 먼저 mysql --version 을 쳐서 실패하는 화면을 캡처하십시오. 그 다음 등록하고 다시 쳐서 성공하는 화면을 캡처합니다. 두 장이 나란히 있으면 「등록하여 환경 설정을 완료하였는가」 가 한눈에 증명됩니다.

준비물 — 관리자 권한이 있는 PC, 실습 2-2 의 계획표

절차 1 — 먼저 «실패하는 화면» 을 캡처합니다

설치하기 전이나, 설치했더라도 PATH 를 걸기 전에 명령 프롬프트에서 칩니다.

mysql --version

'mysql'은(는) 내부 또는 외부 명령... 이라고 나옵니다. 이 화면을 캡처하십시오. 지금 안 찍으면 다시 만들 수 없습니다.

순서가 중요합니다 — 설치부터 끝내 버리면 실패 화면을 만들 수 없습니다. PATH 를 일부러 나중에 거는 것이 아니라, 설치 관리자가 PATH 를 걸어 주지 않는 경우가 있어 이 순서로 하는 것입니다.
절차 2 — 설치합니다
  1. dev.mysql.com 에서 MySQL Installer for Windows 를 내려받습니다.
  2. 설치 종류는 Custom 을 골라 MySQL Server 와 MySQL Workbench 둘을 넣습니다.
  3. 포트는 계획표에 적은 번호를 넣습니다 (3306 이 차 있었다면 3307).
  4. root 비밀번호를 정합니다. 반드시 적어 두십시오. 잊으면 되살리는 데 수업 시간을 다 씁니다.

MySQL 의 계정은 이름과 호스트가 한 쌍입니다. dbconn@localhost 와 dbconn@% 는 다른 계정입니다.

호스트어디서 붙을 수 있는가 쓰는 자리
localhost그 PC 안에서만 서버와 프로그램이 같은 PC 에 있을 때

평가는 원격 접속이 가능해야 한다고 되어 있으므로 % 로 만듭니다.

권한

mysql> CREATE USER 'dbconn'@'%' IDENTIFIED BY 'Zhfldk11!';
mysql> GRANT ALL PRIVILEGES ON bookdb.* TO 'dbconn'@'%';
mysql> FLUSH PRIVILEGES;

mysql> SHOW GRANTS FOR 'dbconn'@'%';   준 권한을 확인

ON bookdb.* 는 bookdb 안의 모든 것이라는 뜻입니다. ON *.* 로 하면 서버의 모든 데이터베이스에 권한을 주게 되므로 실무에서는 쓰지 않습니다. 평가에서는 어느 쪽이든 항목 09 를 충족하지만, 왜 그렇게 했는지 한 줄 적어 두면 좋습니다.

준비물 — mysql> 에 root 로 들어간 상태

절차 1 — 호스트가 무엇인지 먼저 이해합니다

MySQL 계정은 이름 하나가 아니라 이름 + 호스트 한 쌍입니다. dbconn@localhost 와 dbconn@% 는 서로 다른 계정입니다.

호스트어디서 붙을 수 있나쓰는 자리
localhost그 PC 안에서만 서버와 프로그램이 같은 PC 일 때
%어디서든 이번 평가에서 요구하는 것

절차 2 — 계정을 만듭니다

CREATE USER 'dbconn'@'%' IDENTIFIED BY 'Zhfldk11!';

Query OK, 0 rows affected 가 나옵니다. 0 rows 가 정상입니다 — 자료를 넣은 것이 아니라 계정을 만든 것이라서 그렇습니다.

비밀번호가 거부되면 — MySQL 8.0 은 기본으로 길이 8 이상 + 대문자 + 소문자 + 숫자 + 기호를 요구합니다. 1234 같은 것은 받지 않습니다. Zhfldk11! 처럼 네 종류를 섞으십시오.
절차 3 — 권한을 줍니다

GRANT ALL PRIVILEGES ON bookdb.* TO 'dbconn'@'%'; FLUSH PRIVILEGES;

적은 것뜻
ALL PRIVILEGES조회 · 추가 · 수정 · 삭제 · 테이블 만들기 모두
ON bookdb.*bookdb 안의 모든 것 — 다른 DB 에는 손대지 못함
TO 'dbconn'@'%'절차 2 에서 만든 그 계정
왜 ON *.* 로 하지 않는가 — *.* 는 서버의 모든 데이터베이스입니다. mysql 데이터베이스(계정과 권한이 든 곳)까지 열어 주게 됩니다. 평가에서는 어느 쪽이든 항목 09 를 충족하지만, 왜 그렇게 했는지 말할 수 있어야 합니다. 「필요한 데이터베이스에만 줬다」가 바른 답입니다.
절차 4 — 준 권한을 확인합니다

SHOW GRANTS FOR 'dbconn'@'%';

두 줄이 나옵니다. 잘못된 것이 아닙니다.

나온 줄무엇인가
GRANT USAGE ON *.* TO `dbconn`@`%` 「붙을 수는 있다」는 뜻뿐입니다. 계정을 만들면 저절로 붙는 줄이며 권한이 아닙니다
GRANT ALL PRIVILEGES ON `bookdb`.* TO `dbconn`@`%` 이 줄이 우리가 준 권한입니다
절차 5 — 계정 목록에서 호스트를 확인합니다

SELECT user, host FROM mysql.user WHERE user = 'dbconn';

host 칸이 % 인 것이 항목 08 의 근거입니다. 이 화면을 반드시 캡처하십시오.

외래키 (FK)

다른 테이블의 기본키를 가리키는 칸입니다. 가리키는 값이 실제로 있는지 데이터베이스가 대신 지켜 줍니다. 이것을 참조 무결성이라고 합니다.

FOREIGN KEY (Classification_Id)
  REFERENCES Classification_Tbl (Classification_Id)
  ON DELETE CASCADE
삭제 규칙부모가 지워지면쓸 자리
ON DELETE CASCADE자식도 함께 지워집니다 부록처럼 부모가 없으면 뜻이 없는 것
ON DELETE RESTRICT지워지지 않습니다 (기본값) 대여 이력처럼 남겨야 하는 것
ON DELETE SET NULL자식의 그 칸이 비워집니다 가리키는 곳이 없어도 되는 것. 칸이 NULL 을 받아야 합니다

평가도구 예시는 모두 CASCADE 로 되어 있습니다. 그대로 써도 되지만, 이력 테이블에 CASCADE 를 걸면 회원을 지울 때 대여 기록이 사라진다는 점은 알고 쓰는 편이 낫습니다.

절차 2 — 상자 여섯 개를 놓고 칸을 적습니다

PK · FK 표시가 없으면 채점자가 항목 13 · 14 를 확인할 수 없습니다. 그리고도 점수를 못 받는 가장 흔한 까닭입니다. 글자를 굵게 하거나 색을 바꾸지 말고 PK · FK 라고 적으십시오.
절차 3 — 관계선을 잇고 1:N 을 적습니다

CREATE TABLE tbl_member (
  Member_id     INT,

CREATE TABLE 안에 PRIMARY KEY 를 미리 적지 마십시오. 작업지시서가 「alter 사용」 이라고 못 박고 있습니다. 미리 걸어 두면 ALTER 문을 쓸 일이 없어져 항목 04 ~ 07 을 보일 수 없습니다.

다만 FK 를 걸려면 참조되는 칸이 NOT NULL 이어야 문제가 없습니다. 기본키를 나중에 걸 예정이라면 INT NOT NULL 로 만들어 두는 편이 안전합니다.

목적 — 일부러 맨몸으로 만듭니다. 제약조건은 다음 실습에서 ALTER 로 겁니다.

준비물 — MySQL 이 깔린 PC (앞 교과), 작업용 데이터베이스

절차 1 — 작업할 데이터베이스를 정합니다

USE bookdb;

앞 교과에서 만든 bookdb 를 그대로 씁니다. 이 교안의 예제가 모두 bookdb 를 전제로 적혀 있습니다 (뒤의 데이터사전 조회에서 TABLE_SCHEMA='bookdb' 로 찾습니다).

새 데이터베이스를 만들어도 됩니다 — 다만 그렇게 하면 뒤의 사전 조회에서 TABLE_SCHEMA 를 그 이름으로 바꿔야 합니다. 안 바꾸면 결과가 비어 나옵니다. 앞 교과의 테이블(Member_Tbl 등)과 이름이 달라 한 데이터베이스에 있어도 섞이지 않습니다.
절차 2 — 세 테이블을 만듭니다

CREATE TABLE tbl_member ( Member_id INT NOT NULL, Member_name VARCHAR(45), Member_grade VARCHAR(45), Member_phone VARCHAR(45) );

tbl_book(Book_code · book_name · book_author · publisher)과 tbl_rental(Rental_id · Book_code · Member_id · rental_date)도 같은 식으로 만듭니다.

PRIMARY KEY 를 여기에 적지 마십시오. 작업지시서가 「alter 사용」이라고 못 박고 있습니다. 미리 걸어 두면 ALTER 문을 쓸 일이 없어져 항목 04 ~ 07 을 보일 수 없습니다. 결과가 같아도 그 항목은 0점입니다.
절차 3 — 그런데 NOT NULL 은 적습니다

제약조건을 안 거는 것과 NOT NULL 은 다른 이야기입니다. 나중에 기본키를 걸 칸에는 NOT NULL 을 적어 두십시오.

칸왜
Member_id INT NOT NULL 기본키는 비어 있을 수 없습니다. NULL 을 받는 칸에 ALTER 로 기본키를 걸면 MySQL 이 자동으로 NOT NULL 로 바꾸는데, 미리 적어 두는 편이 뜻이 분명합니다

Rental_id INT NOT NULL

수행준거 1.1

명령과 오류

순서가 중요한 이유

외래키는 가리키는 쪽에 기본키가 있어야 걸립니다. 3번(FK)을 1·2번(PK)보다 먼저 실행하면 오류가 납니다. 오류가 나면 대부분 아래 셋 중 하나입니다.

판에 따라 문구가 다릅니다 — MySQL 8.0 은 ERROR 1822 ... Missing index for constraint 'fk_rental_book' in the referenced table 'tbl_book' 처럼 어느 제약조건이 어느 테이블에서 걸렸는지까지 알려 줍니다. 5.7 은 ERROR 1215 Cannot add foreign key constraint 한 줄만 나옵니다. 둘은 같은 뜻입니다 — 가리키려는 칸에 기본키가 없다는 말입니다. 앞 교과에서 8.0 을 깔았다면 1822 를 보게 됩니다.
  1. 참조되는 칸에 기본키나 유일 인덱스가 없습니다 — PK 를 먼저 겁니다.
  2. 두 칸의 자료형이 다릅니다 — INT 와 BIGINT, 부호 있음과 없음이 섞이면 걸리지 않습니다.
  3. 이미 들어 있는 값이 참조되는 곳에 없습니다 — 값을 넣기 전에 제약조건을 먼저 거는 이유입니다.

CASCADE 를 적는 자리

ALTER TABLE tbl_rental
  ADD CONSTRAINT fk_rental_book
  FOREIGN KEY (Book_code) REFERENCES tbl_book (Book_code)
  ON DELETE CASCADE;

제약조건에 이름을 붙여 두면 나중에 지우거나 확인할 때 편합니다. 이름 없이 걸면 tbl_rental_ibfk_1 처럼 저절로 붙습니다.

감점 FK 는 걸었으나 ON DELETE CASCADE 를 빠뜨림

권함 두 FK 모두에 붙입니다. 항목 08 이 5점입니다

실습 2-3 ALTER 로 제약조건 걸기 — 순서가 전부입니다

목적 — 기본키 셋과 외래키 둘을 ALTER 로 겁니다. 채점 항목 04 ~ 08, 15점입니다.

준비물 — 실습 2-2 의 세 테이블

절차 1 — 일부러 «틀린 순서» 로 해 봅니다

왜 순서가 중요한지 한 번 겪어 두면 잊지 않습니다. 기본키를 걸기 전에 외래키부터 걸어 보십시오.

ALTER TABLE tbl_rental ADD CONSTRAINT fk_rental_book FOREIGN KEY (Book_code) REFERENCES tbl_book (Book_code) ON DELETE CASCADE;

ERROR 1822 (HY000): Failed to add the foreign key constraint. Missing index for constraint 'fk_rental_book' in the referenced table 'tbl_book'

「가리키려는 tbl_book 에 색인이 없다」는 말입니다. 기본키가 곧 색인이므로, 기본키를 먼저 걸어야 합니다.

5.7 을 쓰면 문구가 다릅니다 — ERROR 1215 Cannot add foreign key constraint 한 줄만 나옵니다. 같은 뜻이지만 8.0 이 훨씬 친절합니다.
절차 2 — 기본키를 셋 겁니다

ALTER TABLE tbl_member ADD CONSTRAINT pk_member PRIMARY KEY (Member_id); ALTER TABLE tbl_book ADD CONSTRAINT pk_book PRIMARY KEY (Book_code); ALTER TABLE tbl_rental ADD CONSTRAINT pk_rental PRIMARY KEY (Rental_id);

각각 Query OK, 0 rows affected 이 나옵니다. 값이 없으니 0 rows 가 정상입니다.

절차 3 — 외래키를 둘 겁니다

ALTER TABLE tbl_rental ADD CONSTRAINT fk_rental_book FOREIGN KEY (Book_code) REFERENCES tbl_book (Book_code) ON DELETE CASCADE; ALTER TABLE tbl_rental ADD CONSTRAINT fk_rental_member FOREIGN KEY (Member_id) REFERENCES tbl_member (Member_id) ON DELETE CASCADE;

ON DELETE CASCADE 를 빠뜨리면 외래키는 걸리지만 항목 08(5점)을 놓칩니다. 작업지시서에 적힌 삭제 규칙을 그대로 옮기십시오.

가리키는 칸에 기본키가 없다 절차 2 를 먼저 합니다
두 칸의 자료형이 다르다
INT 와 BIGINT, 부호 있음/없음		 DESC 로 두 칸을 견주어 맞춥니다
이미 들어 있는 값이 가리키는 곳에 없다 값을 넣기 전에 제약조건을 거는 까닭입니다. 이미 넣었다면 어긋난 줄을 지우고 다시 겁니다

근거

명령

COMMIT · ROLLBACK

왜 묶는가

대여를 한 건 처리하려면 대여 기록을 넣고 도서 상태를 바꾸는 두 가지가 함께 되어야 합니다. 앞의 것만 되고 뒤의 것이 실패하면 데이터가 어긋난 채로 남습니다. 그래서 둘을 한 덩어리로 묶고, 다 되면 확정하고 하나라도 안 되면 통째로 되돌립니다.

실습해 보기

START TRANSACTION;
DELETE FROM tbl_rental WHERE Rental_id = 2;
SELECT * FROM tbl_rental;     -- 나에게는 지워져 보입니다

-- 다른 창을 하나 더 열어 같은 조회를 해 보십시오. 아직 남아 있습니다.

ROLLBACK;
SELECT * FROM tbl_rental;     -- 되돌아왔습니다

이 수행준거는 이번 평가도구에 대응하는 채점 항목이 없습니다. 다만 능력단위의 수행준거이고 다음 교과의 서버 프로그램에서 바로 쓰이므로 함께 다룹니다.

목적 — 지운 것을 되살립니다. 이번 채점표에는 대응 항목이 없지만 수행준거 1.3 이고, 다음 교과의 서버 프로그램에서 바로 쓰입니다.

절차 5 — 되돌립니다

2건으로 돌아옵니다. 지운 줄이 되살아난 것입니다.

시점내 화면다른 창
START TRANSACTION 전2건2건
DELETE 뒤1건2건

START TRANSACTION; DELETE FROM tbl_rental WHERE Rental_id = 2; COMMIT; SELECT COUNT(*) FROM tbl_rental;

절차 7 — 왜 묶는지 한 줄로 적어 둡니다

서술형에서 물을 수 있습니다.

대여 한 건을 처리하려면 «대여 기록을 넣는 것» 과 «도서 상태를 바꾸는 것» 이 함께 되어야 한다. 앞만 되고 뒤가 실패하면 장부가 어긋나므로, 둘을 한 덩어리로 묶어 다 되면 확정하고 하나라도 안 되면 통째로 되돌린다.

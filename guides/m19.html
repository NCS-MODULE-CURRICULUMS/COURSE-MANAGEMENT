「환경 구축」 은 «설치» 가 아닙니다. 다음 버튼을 열 번 누르면 설치는 끝납니다. 그것만으로는 이 교과가 끝나지 않습니다. 무엇이 어디에 깔렸고, 왜 그렇게 정했고, 다른 사람이 같은 것을 다시 만들 수 있는가 까지가 이 교과입니다. 그래서 적는 일이 절반입니다.

왜 운영체제부터 배우는가

개발 도구는 운영체제 위에 얹혀 돕니다. 도구가 말을 안 들을 때 도구를 아무리 들여다봐도 답이 안 나오는 경우가 많습니다. 원인이 운영체제 쪽에 있기 때문입니다.

이런 일이 생기면실은 운영체제 쪽 문제입니다
javac 가 없다고 나옴 PATH 에 설치 자리가 안 들어갔습니다 (실습 12)
프로그램을 띄웠는데 포트가 이미 쓰인다고 함 앞에 띄운 것이 아직 돌고 있습니다 (실습 9)
파일을 못 찾는다고 함 지금 어느 폴더에 있는지를 잘못 알고 있습니다 (실습 5)
한글이 깨져서 나옴 코드페이지가 다릅니다 (실습 5)

네 가지가 이 교과의 절반입니다. 뒤 교과에서 만나는 문제의 상당수가 이 넷 중 하나입니다.

「확인한 명령」 칸이 이 표의 값어치입니다. 값만 아홉 줄 적어 놓으면 어디서 가져온 숫자인지 알 수 없습니다. 명령을 함께 적어 두면 채점자가 그 자리에서 다시 쳐 볼 수 있습니다. 「내 컴퓨터 속성에서 봤습니다」 는 다시 해 볼 수가 없습니다.

학습모듈은 운영체제를 「하드웨어와 소프트웨어 기능을 쓸 수 있게 해 주는 시스템 소프트웨어」 로 정의합니다. 한정된 자원을 나눠 쓰게 관리하고 사람과 컴퓨터 사이에 끼어 줍니다.

학습모듈이 드는 주요 기능은 열 가지입니다. 외울 것은 아니고, 뒤에서 문제가 났을 때 어느 기능 탓인지 짚을 수 있으면 됩니다.

왜 서버는 리눅스인가
무료라서만은 아닙니다. GUI 없이 돌릴 수 있어 자원을 덜 먹고, 명령으로 다 되기 때문에 같은 작업을 스크립트로 적어 두고 되풀이할 수 있습니다. 이 교안이 CLI 를 강조하는 까닭과 같습니다 (1절).

systeminfo 만 치면 수십 줄이 쏟아집니다. | findstr 을 붙이면 찾는 줄만 남습니다 — | 는 「앞의 결과를 뒤로 넘긴다」 는 뜻입니다.

둘 다 «같은» 명령입니다. chcp 는 「이 창이 글자를 어떤 규칙으로 읽을지」 를 정합니다. 949 는 한국어 규칙, 65001 은 UTF-8 입니다. 위에서는 메시지가 한국어로 나오고 선도 제대로 그려지고, 아래에서는 메시지가 영어로 바뀌고 선이 깨집니다.

학습모듈 2-2

산출물

확인서 개발도구 칸

학습모듈은 JDK 를 「자바로 프로그램을 만들고 실행하는 데 필요한 모든 것을 담은 도구 모음」 이라고 적습니다. 안에 이런 것들이 들어 있습니다.

들어 있는 것
javac컴파일러. 사람이 쓴 .java 를 컴퓨터가 읽는 .class 로 바꿉니다
JRE실행 환경. .class 를 돌립니다
javadoc주석에서 문서를 뽑습니다

JDK 와 JRE 를 헷갈립니다. JRE 만 있으면 «돌릴» 수는 있어도 «만들» 수는 없습니다. java 는 되는데 javac 가 없다면 JRE 만 깔린 것입니다 — JDK 를 받으십시오.

설치되었는지 확인하는 세 줄

> java -version openjdk version "21.0.2" 2024-01-16 OpenJDK Runtime Environment (build 21.0.2+13-58) OpenJDK 64-Bit Server VM (build 21.0.2+13-58, mixed mode, sharing) > javac -version javac 21.0.2 > where java C:\jdk-21.0.2\bin\java.exe

이 줄이 증명하는 것
java -version돌릴 수 있다
javac -version만들 수 있다 — JDK 가 맞다
where java어디에 깔렸는지 — 확인서에 적을 자리

셋을 «다» 찍으십시오. java -version 만 찍으면 JRE 인지 JDK 인지 알 수 없습니다.

두 판이 섞여 있을 때

> where java C:\Program Files\Common Files\Oracle\Java\javapath\java.exe C:\jdk-21.0.2\bin\java.exe

여러 줄이 나오면 맨 위의 것이 실제로 돕니다 (실습 8). java -version 이 내가 깐 판과 다르게 나오면 이 경우입니다 — PATH 에서 내 JDK 를 앞으로 옮기십시오.

12JAVA_HOME 과 PATH

둘은 하는 일이 다릅니다.

근거

학습모듈 2-2 · 환경변수

주의

창을 다시 열어야 합니다

둘의 차이

무엇을 위한 것없으면
PATH 내가 java 라고만 쳐도 찾아 주게 java 가 없다고 나옵니다
JAVA_HOME 다른 도구가 JDK 자리를 물어볼 때 답해 주게 그 도구에 따라 다릅니다 — 아래

실제로 재 봤습니다

> echo %JAVA_HOME% %JAVA_HOME% ← 안 잡혀 있습니다 (실습 8) > java -version openjdk version "21.0.2" 2024-01-16 ← 그래도 됩니다 > javac -version javac 21.0.2 ← 이것도 됩니다 > gradle --version Gradle 8.14.5 ← 이것도 됩니다

JAVA_HOME 이 없어도 «되는 것이 많습니다». java · javac · gradle 은 PATH 만으로 돌아갑니다. 그래서 「java 가 되니까 다 된 것」 이라고 넘어가기 쉽습니다.
그런데 도구에 따라 JAVA_HOME 을 «직접» 찾는 것이 있습니다. 그때는 「JAVA_HOME 이 설정되지 않았습니다」 로 멈춥니다. 미리 잡아 두면 그 자리에서 안 막힙니다 — 학습모듈이 설치 직후에 잡으라고 적어 둔 까닭입니다.

잡는 법

# 이 창에서만 (꺼지면 사라집니다) > set JAVA_HOME=C:\jdk-21.0.2 # 계속 남게 (다음부터 열리는 창에 적용) > setx JAVA_HOME "C:\jdk-21.0.2" 성공: 지정한 값을 저장했습니다.

setx 로 잡은 값은 «지금 창» 에는 안 들어옵니다. setx 는 다음부터 열리는 창에 적용됩니다. 바로 echo %JAVA_HOME% 을 쳐 보면 여전히 %JAVA_HOME% 입니다. 「안 먹혔네」 하고 또 칩니다. 창을 닫고 다시 열어 확인하십시오. GUI(시스템 속성)에서 고쳤을 때도 똑같습니다 (실습 7).

한 줄에 쳐도 «안 보이는» 까닭

> set JAVA_HOME=C:\jdk-21.0.2 & echo %JAVA_HOME% %JAVA_HOME% ← 방금 잡았는데 «안» 나옵니다 > set JAVA_HOME=C:\jdk-21.0.2 & call echo %%JAVA_HOME%% C:\jdk-21.0.2 ← 이렇게 하면 나옵니다

%변수% 는 «줄을 읽을 때» 값이 정해집니다. & 로 이은 한 줄은 통째로 먼저 읽힙니다. 읽는 시점에는 JAVA_HOME 이 아직 없으므로 %JAVA_HOME% 글자 그대로 남습니다.
같은 일이 종료 코드에서도 일어납니다 — rd z & echo %errorlevel% 는 rd 가 실패해도 0 을 보여 줍니다. 「한 줄에 이어 치지 말고 줄을 나누십시오.」

확인은 «새 창» 에서

# 창을 닫고 새로 연 뒤 > echo %JAVA_HOME% C:\jdk-21.0.2 > where java C:\jdk-21.0.2\bin\java.exe

이 두 줄이 확인서의 환경변수 칸이 됩니다.

java -Dfile.encoding=UTF-8 Hello 안 됩니다 — 화면 출력과 상관없는 설정입니다
java -Dstdout.encoding=UTF-8 Hello됩니다
세 가지를 다 재 본 결과입니다. file.encoding 은 파일을 읽고 쓸 때의 규칙이고, stdout.encoding 이 화면에 내보낼 때의 규칙입니다. 이름이 비슷해 file.encoding 부터 건드리게 되는데 화면 깨짐에는 소용이 없습니다.

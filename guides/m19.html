학습모듈은 실제 회사를 가정합니다 — 서버가 여럿이고 운영체제가 제각각이라 장비 구분 · 서버명 · 설치 소프트웨어 · 운영체제 를 표로 만들어 둡니다.

우리에게는 컴퓨터가 한 대뿐입니다. 그래도 같은 일을 합니다 — 한 줄짜리 표를 만듭니다. 표가 한 줄이라고 안 만들면, 뒤에서 「내 컴퓨터가 64비트였나」 를 매번 다시 찾게 됩니다.

왜 이것을 «먼저» 하는가

모르면이렇게 됩니다
비트 수 (x64 / ARM) JDK 를 잘못 받습니다. 설치는 되는데 안 돕니다
운영체제 판 도구가 이 판을 지원하는지 알 수 없습니다
남은 디스크 IDE 하나가 1 GB 가 넘습니다. 설치하다 멈춥니다
실습 2 한 줄짜리 정보 자산 목록 을 만듭니다 — 비트 수부터 봅니다

목적 — 학습모듈은 서버가 여럿인 회사를 가정하고 장비별 표를 만들게 합니다. 우리는 컴퓨터가 한 대지만 같은 일을 한 줄로 합니다. 이걸 안 하면 JDK 를 잘못 받습니다.

절차 1 — 세 가지를 명령으로 봅니다

> systeminfo | findstr /B /C:"OS 이름" /C:"OS 버전" /C:"시스템 종류" OS 이름: Microsoft Windows 11 Home OS 버전: 10.0.26200 N/A 빌드 26200 시스템 종류: x64-based PC

보는 것왜 중요한가
시스템 종류 가장 중요합니다. x64 인지 ARM64 인지에 따라 받을 JDK 가 다릅니다
OS 이름Home 인지 Pro 인지 — 되는 기능이 다릅니다
OS 버전도구가 이 판을 지원하는지 볼 때
비트 수를 안 보고 받으면 «설치는 되는데 안 돕니다». 요즘 노트북 중에는 ARM64 도 있습니다. x64 용 JDK 를 깔아도 일단 깔립니다. 그런데 돌려 보면 느리거나 오류가 납니다 — 원인을 찾는 데 하루가 갑니다. 먼저 한 줄 확인하는 데 십 초입니다.

실습 6 지우는 명령은 휴지통으로 안 갑니다 — 지우기 전에 봅니다

목적 — 만들고 옮기는 것은 안 해도 알 만합니다. 지우는 것이 다릅니다. 탐색기에서 지운 것은 되살릴 수 있지만 명령으로 지운 것은 그냥 없어집니다.

절차 1 — 복사하고 이름 바꾸고 옮깁니다

> copy src\hello.txt docs\ 1개 파일이 복사되었습니다. > cd docs > ren hello.txt readme.txt > dir /b readme.txt > cd .. > move docs\readme.txt build\ 1개 파일을 이동했습니다.

명령원래 것은리눅스
copy남습니다cp
move없어집니다mv
ren이름만 바뀝니다mv

리눅스는 mv 하나가 옮기기와 이름 바꾸기를 다 합니다. 같은 일을 두 이름으로 부르는 것이 아니라, 「옮기는 것」 과 「이름 바꾸는 것」 이 원래 같은 일이기 때문입니다 — 자리를 바꾸는 것이니까요.

절차 2 — ren 에 «경로를 붙이면» 안 됩니다

> ren docs\hello.txt docs\readme.txt 명령 구문이 올바르지 않습니다. > ren docs\hello.txt readme.txt (됩니다)

ren 은 「어디 있는 무엇을」 + 「새 이름」 입니다. 새 이름 쪽에는 경로를 못 씁니다 — 이름만 바꾸는 것이지 옮기는 것이 아니기 때문입니다. 옮기려면 move 입니다.

절차 3 — 폴더를 지워 봅니다

> rd src 디렉터리가 비어 있지 않습니다. > dir /b src hello.txt ← 안에 이것이 있었습니다 > rd /s /q src (아무 말 없이 지워집니다)

붙이는 것
/s안에 든 것까지 다
/q물어보지 않고 (quiet)
rd /s /q 와 del 은 휴지통을 «거치지 않습니다». 탐색기에서 지우면 휴지통에 들어가 되살릴 수 있습니다. 명령으로 지우면 그냥 없어집니다. /q 를 붙이면 「정말 지울까요」 도 안 물어봅니다.
지우기 전에 dir /b 로 한 번 보는 습관을 들이십시오 — 이 한 줄이 나중에 하루를 아껴 줍니다.
절차 4 — 「오류가 떴는데 성공」 을 겪습니다

이 교과에서 가장 중요한 한 가지입니다.

> rd z 디렉터리가 비어 있지 않습니다. ← 실패했습니다 > echo %errorlevel% 0 ← 그런데 0 («성공») 입니다

# 다른 창에서 이 명령만 따로 돌려 보면 $ cmd /c "rd z" $ echo 종료 코드 = $? 종료 코드 = 145 ← 실은 145 («실패») 였습니다

화면의 오류 메시지와 «종료 코드» 는 다른 것입니다. 종료 코드는 프로그램이 남기는 숫자 한 개입니다 — 0 이면 성공, 0 이 아니면 실패로 약속되어 있습니다. 나중에 스크립트를 쓸 때 이 숫자로 판단합니다 (뒤 교과).
그런데 %errorlevel% 은 «줄을 읽을 때» 값이 정해집니다. 그래서 실패한 직후에 물어봐도 옛 값이 나올 수 있습니다. 「화면에 오류가 떴으니 실패」 는 맞지만 「%errorlevel% 이 0 이니 성공」 은 믿으면 안 됩니다.

PATH 를 보는 법

> echo %PATH% C:\Users\jwg13\bin;C:\Program Files\Git\mingw64\bin;…;C:\jdk-21.0.2\bin;…

> echo %PATH% | findstr /i jdk (jdk 가 들어간 부분이 있으면 그 줄이 나옵니다)

안 잡힌 변수는 이렇게 보입니다

실습 8 where 하나면 어느 것이 도는지 압니다

절차 1 — 없는 명령을 «일부러» 쳐 봅니다

근거

학습모듈 2-2

산출물

확인서 개발도구 칸

JDK 가 무엇인가

학습모듈은 JDK 를 「자바로 프로그램을 만들고 실행하는 데 필요한 모든 것을 담은 도구 모음」 이라고 적습니다. 안에 이런 것들이 들어 있습니다.

들어 있는 것
javac컴파일러. 사람이 쓴 .java 를 컴퓨터가 읽는 .class 로 바꿉니다
JRE실행 환경. .class 를 돌립니다
javadoc주석에서 문서를 뽑습니다
jdb디버거
JDK 와 JRE 를 헷갈립니다. JRE 만 있으면 «돌릴» 수는 있어도 «만들» 수는 없습니다. java 는 되는데 javac 가 없다면 JRE 만 깔린 것입니다 — JDK 를 받으십시오.

설치되었는지 확인하는 세 줄

> java -version openjdk version "21.0.2" 2024-01-16 OpenJDK Runtime Environment (build 21.0.2+13-58) OpenJDK 64-Bit Server VM (build 21.0.2+13-58, mixed mode, sharing) > javac -version javac 21.0.2 > where java C:\jdk-21.0.2\bin\java.exe

이 줄이 증명하는 것
java -version돌릴 수 있다
javac -version만들 수 있다 — JDK 가 맞다
where java어디에 깔렸는지 — 확인서에 적을 자리

셋을 다 찍으십시오. java -version만 찍으면 JRE 인지 JDK 인지 알 수 없습니다.

두 판이 섞여 있을 때

> where java C:\Program Files\Common Files\Oracle\Java\javapath\java.exe C:\jdk-21.0.2\bin\java.exe

여러 줄이 나오면 맨 위의 것이 실제로 돕니다 (실습 8). java -version 이 내가 깐 판과 다르게 나오면 이 경우입니다 — PATH 에서 내 JDK 를 앞으로 옮기십시오.

절차 1 — 받기 전에 «두 가지» 를 정합니다
정할 것

판 21 을 권합니다. 오래 지원되는 판(LTS)이고 이 과정의 뒤 교과들이 21 을 씁니다
JDK 와 JRE 를 헷갈리는 일이 아주 흔합니다. JRE 만 있으면 «돌릴» 수는 있어도 «만들» 수 없습니다. 받을 때 이름에 JDK 가 들어 있는지 보십시오. 깔고 나서 확인하는 법은 절차 3 입니다.
절차 2 — 설치 자리를 «기억할 수 있게» 정합니다

「Program Files」 에는 빈칸이 있습니다. 명령에서 경로를 쓸 때마다 따옴표로 감싸야 하고, 따옴표를 빼먹으면 「Program」 까지만 읽힙니다. 빈칸 없는 짧은 자리에 두면 이 문제가 사라집니다.

여러 줄이 나오면 맨 위의 것이 돕니다 (실습 8). 내가 깐 판과 다르게 나오는 것은 거의 늘 이 경우입니다 — PATH 에서 내 JDK 를 앞으로 옮기십시오 (실습 12).

12JAVA_HOME 과 PATH

둘은 하는 일이 다릅니다.

근거

학습모듈 2-2 · 환경변수

주의

창을 다시 열어야 합니다

둘의 차이

무엇을 위한 것없으면
PATH 내가 java 라고만 쳐도 찾아 주게 java 가 없다고 나옵니다
JAVA_HOME 다른 도구가 JDK 자리를 물어볼 때 답해 주게 그 도구에 따라 다릅니다 — 아래

실제로 재 봤습니다

> echo %JAVA_HOME% %JAVA_HOME% ← 안 잡혀 있습니다 (실습 8) > java -version openjdk version "21.0.2" 2024-01-16 ← 그래도 됩니다 > javac -version javac 21.0.2 ← 이것도 됩니다 > gradle --version Gradle 8.14.5 ← 이것도 됩니다

JAVA_HOME 이 없어도 «되는 것이 많습니다». java · javac · gradle 은 PATH 만으로 돌아갑니다. 그래서 「java 가 되니까 다 된 것」 이라고 넘어가기 쉽습니다.
그런데 도구에 따라 JAVA_HOME 을 «직접» 찾는 것이 있습니다. 그때는 「JAVA_HOME 이 설정되지 않았습니다」 로 멈춥니다. 미리 잡아 두면 그 자리에서 안 막힙니다 — 학습모듈이 설치 직후에 잡으라고 적어 둔 까닭입니다.

잡는 법

# 이 창에서만 (꺼지면 사라집니다) > set JAVA_HOME=C:\jdk-21.0.2 # 계속 남게 (다음부터 열리는 창에 적용) > setx JAVA_HOME "C:\jdk-21.0.2" 성공: 지정한 값을 저장했습니다.

setx 로 잡은 값은 «지금 창» 에는 안 들어옵니다. setx 는 다음부터 열리는 창에 적용됩니다. 바로 echo %JAVA_HOME% 을 쳐 보면 여전히 %JAVA_HOME% 입니다. 「안 먹혔네」 하고 또 칩니다. 창을 닫고 다시 열어 확인하십시오. GUI(시스템 속성)에서 고쳤을 때도 똑같습니다 (실습 7).

한 줄에 쳐도 «안 보이는» 까닭

> set JAVA_HOME=C:\jdk-21.0.2 & echo %JAVA_HOME% %JAVA_HOME% ← 방금 잡았는데 «안» 나옵니다 > set JAVA_HOME=C:\jdk-21.0.2 & call echo %%JAVA_HOME%% C:\jdk-21.0.2 ← 이렇게 하면 나옵니다

%변수% 는 «줄을 읽을 때» 값이 정해집니다. & 로 이은 한 줄은 통째로 먼저 읽힙니다. 읽는 시점에는 JAVA_HOME 이 아직 없으므로 %JAVA_HOME% 글자 그대로 남습니다.
같은 일이 종료 코드에서도 일어납니다 — rd z & echo %errorlevel% 는 rd 가 실패해도 0 을 보여 줍니다. 「한 줄에 이어 치지 말고 줄을 나누십시오.」

확인은 «새 창» 에서

# 창을 닫고 새로 연 뒤 > echo %JAVA_HOME% C:\jdk-21.0.2 > where java C:\jdk-21.0.2\bin\java.exe

이 두 줄이 확인서의 환경변수 칸이 됩니다.

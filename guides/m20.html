# 자바 public class Sum { public static void main(String[] a) { long t = 0; for (int i = 1; i <= 50_000_000; i++) t += i; System.out.println("합계 = " + t); } }

세 줄로 끝나는 것과 일곱 줄이 필요한 것의 차이가 벌써 보입니다. 파이썬은 변수의 «종류» 를 안 적어도 되고 감싸는 class 도 없습니다. 「어느 쪽이 좋은가」 가 아닙니다 — 무엇을 덜 적게 하고 대신 무엇을 포기했는가 입니다 (실습 3).

절차 1 — 세 파일을 만듭니다

# Sum.java public class Sum { public static void main(String[] a) { long t = 0; for (int i = 1; i <= 50_000_000; i++) t += i; System.out.println("합계 = " + t); } }

# sum.py t = 0 for i in range(1, 50_000_001): t += i print("합계 =", t)

# sum.js (노드가 있으면) let t = 0n; for (let i = 1n; i <= 50000000n; i++) t += i; console.log("합계 =", t.toString());

절차 2 — 셋 다 «같은 답» 인지 봅니다

합계 = 1250000025000000

답이 다르면 «견주기 전에» 고쳐야 합니다. 가장 흔한 까닭은 숫자가 담기는 «크기» 입니다. 자바에서 long 을 int 로 하면 넘쳐서 «틀린 답» 이 나옵니다 — 오류는 안 납니다.
이것 자체가 언어 특성입니다 — 「종류를 적는 언어」 가 무엇을 «막아 주지 못하는지» 여기서 한 번 보십시오.
절차 3 — int 로 바꿔 «일부러» 틀려 봅니다

# long t 를 int t 로 바꾸면 합계 = 1333106752 ← 맞는 답은 1250000025000000 입니다

int 는 약 21억까지밖에 못 담습니다. 넘치면 한 바퀴 돌아 엉뚱한 값이 됩니다.

«음수도 아니고» 그럴듯한 양수가 나온 것을 보십시오. 한 바퀴 돌 때마다 음수와 양수를 오가므로 마지막에 어디에 서 있느냐에 따라 부호가 달라집니다.
「음수면 넘친 것」 이라고 외우면 안 됩니다. 오류도 안 나고 부호도 멀쩡하면 맞는 답을 미리 알지 못하는 한 못 알아챕니다 — 그래서 시험(실습 11)이 필요합니다.

다만 「반복이 아주 많은 계산」 에서 인터프리터가 느리다 는 것은 방식에서 오는 차이라 대체로 그렇습니다 — 한 줄씩 번역하면서 돌기 때문입니다.

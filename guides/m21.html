선수 학습

개발자 환경 구축

「기초」 라는 말의 뜻

세 분야는 각각 한 학기짜리 과목입니다. 이 교과는 거기까지 안 갑니다. 응용SW 개발자가 «알아야 하는 만큼» 만 합니다.

분야여기서 하는 것여기서 «안» 하는 것
네트워크 계층을 알고 막혔을 때 어디를 볼지 안다 라우터 설정 · 방화벽 정책
미들웨어 무엇이 가운데 있는지 알고 띄운다 WAS 튜닝 · 클러스터 구성
데이터베이스 테이블을 만들고 다룬다 인덱스 튜닝 · 백업 · 이중화

왜 이 셋인가

브라우저에서 「예약하기」 를 눌렀을 때 ① 네트워크 요청이 서버까지 «갑니다» ② 미들웨어 서버에서 «받아» 어느 코드가 처리할지 정합니다 ③ 데이터베이스 예약을 «저장» 합니다 ② 결과를 «만들어» 돌려줍니다 ① 응답이 브라우저로 «돌아옵니다»

셋 중 하나만 막혀도 화면이 안 뜹니다. 그런데 화면에는 똑같이 「안 됩니다」 로 보입니다 — 어디가 막혔는지 가르는 것이 이 교과의 값어치입니다.

이 교안이 쓰는 것

네트워크 윈도우 기본 명령 — ipconfig · ping · nslookup · curl 미들웨어 앞 교과에서 만든 스프링 부트 프로그램 (WAS 가 들어 있습니다) 데이터베이스 MySQL 8.0 — 도커 컨테이너로 띄웁니다 예제 공공 체육시설 예약 — 앞 교과들과 같은 예제

데이터베이스를 도커로 띄우는 까닭은 설치에 시간을 덜 쓰기 위해서입니다. MySQL 을 컴퓨터에 직접 설치하면 계정과 서비스 설정에 한참이 걸리고, 지울 때도 깨끗이 안 지워집니다. 도커는 명령 한 줄로 띄우고 한 줄로 내립니다. 수업이 끝나면 컨테이너를 내리고, 다음 시간에 같은 명령으로 다시 띄우면 됩니다.

하나만 막혀도 화면은 «똑같이» 안 뜹니다

막힌 곳실제로 일어난 일 화면에는
① 네트워크 서버 주소를 못 찾음 · 포트가 막힘 「안 됩니다」
— 셋 다 비슷하게 보입니다
② 미들웨어 WAS 가 안 떠 있음 · 주소에 맞는 코드가 없음
③ DB DB 가 안 떠 있음 · 제약 조건에 걸림
이 교과의 값어치가 여기 있습니다. 「어디가 막혔는지 «가르는» 일」 입니다. 셋을 다 알아야 한 걸음씩 좁혀 갈 수 있습니다 — 모르면 처음부터 다시 만들게 됩니다.

가르는 순서는 «바깥에서 안으로»

① 서버까지 «가는가» ping · telnet · curl (실습 6 · 7) ② 서버가 «받았는가» WAS 로그 (실습 9) ③ DB 까지 «갔는가» DB 로그 · SQL 직접 실행 (실습 14)

순서를 지키면 대개 두세 걸음에 찾습니다. 거꾸로 가면 DB 를 아무리 봐도 원인이 안 나옵니다 — 요청이 서버에 닿지도 않았기 때문입니다.

프로토콜이란

학습모듈은 원래 외교 용어라고 적습니다 — 「국가 간의 교류를 원활하게 하려고 정한 의례나 약속」. 네트워크 프로토콜은 「통신을 «통제하는 규칙» 들을 모아 놓은 것」 입니다.

세 요소무엇택배로 비유하면
구문 (syntax) 데이터의 구조나 형식 송장을 어떤 양식으로 쓰나
의미 (semantics) 각 부분이 무엇을 뜻하나 이 칸이 받는 사람, 저 칸이 주소
타이밍 (timing) 언제 보내고 얼마나 빨리 언제 · 며칠 만에 오나

세 가지가 «사전에» 정해져 있어야 주고받을 수 있습니다. 보내는 쪽과 받는 쪽이 같은 규칙을 알아야 한다는 뜻입니다.

왜 «층» 으로 나누나

층을 안 나누면 프로그램이 «전선의 전기 신호» 까지 알아야 합니다 층을 나누면 프로그램은 «HTTP» 만 알면 되고 아래가 알아서 «전기 신호» 까지 내려보냅니다

한 층을 갈아 끼워도 위아래가 안 바뀝니다 — 유선을 무선으로 바꿔도 브라우저는 그대로 입니다.

서브넷 마스크가 하는 일

5이름이 주소로

DNS 가 하는 일을 한 번에 봅니다.

도구

nslookup

사람은 이름을, 컴퓨터는 주소를

사람이 치는 것 example.com 컴퓨터가 쓰는 것 104.20.23.154 그 사이를 «DNS» 가 이어 줍니다

직접 물어봅니다

> nslookup example.com 8.8.8.8 서버: UnKnown Address: 8.8.8.8 이름: example.com Addresses: 2606:4700:10::6814:179a 2606:4700:10::ac42:93f3 104.20.23.154 172.66.147.243

보이는 것
서버: UnKnown 정상입니다. 물어본 DNS 서버(8.8.8.8)의 «이름» 을 모른다는 뜻일 뿐입니다
주소가 넷 한 이름에 주소가 여럿일 수 있습니다 — 나눠서 받으려고 그렇게 합니다
2606:4700:… IPv6 주소입니다. 콜론으로 나뉩니다
IPv4 와 IPv6 가 «같이» 나오는 것이 정상입니다. IPv4 는 104.20.23.154 처럼 점 세 개, IPv6 는 2606:4700:10::6814:179a 처럼 콜론입니다. IPv4 가 모자라서 IPv6 를 만들었고, 지금은 둘이 같이 쓰입니다 — 앞 교과 netstat 에서 줄이 둘씩 나온 까닭입니다.

「이름을 못 찾습니다」 가 나오면

확인 순서
① nslookup 이 되나 안 되면 DNS 문제 — 3층 아래
② 주소로 직접 가 보면 되면 DNS 만 문제. 안 되면 길 문제 (실습 6)

요청이 옴 → WAS 가 내 코드를 부른다 → 결과를 돌려준다

12ERD

근거

학습모듈 3-2

용어

ERD

ERD 란

Entity-Relationship Diagram — 「무엇이 있고 서로 어떻게 이어지는가」 를 그린 그림입니다. 표를 만들기 전에 그립니다.

┌──────────┐ ┌──────────┐ ┌──────────┐ │ 회원 │ │ 예약 │ │ 시설 │ ├──────────┤ ├──────────┤ ├──────────┤ │ 회원번호 PK│───1:N──│ 예약번호 PK│──N:1───│ 시설번호 PK│ │ 아이디 U │ │ 회원번호 FK│ │ 이름 │ │ 이름 │ │ 시설번호 FK│ │ 지역 │ └──────────┘ │ 이용일 │ │ 요금 │ │ 인원 │ │ 실내여부 │ └──────────┘ └──────────┘

표시
PK기본키 — 그 행을 가리키는 번호
FK외래키 — 다른 표를 가리킴
U유일 — 겹치면 안 되는 칸 (아이디)
1:N회원 하나가 예약 여럿을 합니다

관계 셋

관계보기표로 만들면
1:1회원 — 회원상세둘 중 한쪽에 FK
1:N회원 — 예약N 쪽에 FK
N:M시설 — 편의시설 가운데 표를 하나 만듭니다
1:N 은 «N 쪽» 에 FK 를 둡니다. 회원 한 명이 예약을 열 건 할 수 있는데, 회원 표에 예약번호 열 개를 넣을 칸은 만들 수 없습니다. 예약 표에 «회원번호» 한 칸을 두면 끝납니다 — 이것이 1:N 을 표로 만드는 유일한 방법입니다.

그리는 순서

① 명사를 찾습니다 회원 · 시설 · 예약 ② 각 명사의 항목을 적습니다 이름 · 요금 · 이용일 ③ 기본키를 정합니다 회원번호 · 시설번호 · 예약번호 ④ 관계를 긋습니다 회원 1:N 예약 N:1 시설 ⑤ FK 를 N 쪽에 둡니다

「예약」 처럼 «둘을 잇는» 것이 대개 가운데 옵니다 — 양쪽을 가리키는 FK 가 둘입니다.

ERD 를 CREATE 로 옮긴다

앞 실습에서 그린 표 셋을 그대로 옮겨 적습니다. 상자 하나가 테이블 하나, 상자 안의 줄 하나가 열 하나입니다. PK 와 FK 로 적어 둔 것이 PRIMARY KEY 와 FOREIGN KEY 가 됩니다.

CREATE DATABASE sportdb DEFAULT CHARACTER SET utf8mb4; USE sportdb; CREATE TABLE facility ( facility_id INT PRIMARY KEY, name VARCHAR(50) NOT NULL, region VARCHAR(20) NOT NULL, fee INT NOT NULL, indoor BOOLEAN NOT NULL ); CREATE TABLE member ( member_id INT PRIMARY KEY, login_id VARCHAR(20) NOT NULL UNIQUE, name VARCHAR(20) NOT NULL ); CREATE TABLE reservation ( reservation_id INT PRIMARY KEY, member_id INT NOT NULL, facility_id INT NOT NULL, use_date DATE NOT NULL, headcount INT NOT NULL, FOREIGN KEY (member_id) REFERENCES member(member_id), FOREIGN KEY (facility_id) REFERENCES facility(facility_id) );

mysql> SHOW TABLES; Tables_in_sportdb facility member reservation

utf8mb4 로 만든 것에 주의합니다. 한글을 담으려면 필요하고, 이모지까지 담으려면 반드시 utf8mb4 여야 합니다. 예전 utf8 은 이름만 utf8 이고 실제로는 세 바이트까지만 담습니다.

제약을 일부러 어겨 본다

제약은 적어 놓기만 해서는 무엇을 막는지 알 수 없습니다. 한 번씩 어겨 보면 어떤 오류가 나는지 몸에 남습니다. 오류 번호도 함께 보아 두십시오. 실무에서 로그를 읽을 때 이 번호로 원인을 찾습니다.

mysql> INSERT INTO facility VALUES (1,'또중앙','달서구',2000,TRUE); ERROR 1062 (23000): Duplicate entry '1' for key 'facility.PRIMARY' mysql> INSERT INTO facility VALUES (9,NULL,'달서구',2000,TRUE); ERROR 1048 (23000): Column 'name' cannot be null mysql> INSERT INTO member VALUES (9,'kim','다른김'); ERROR 1062 (23000): Duplicate entry 'kim' for key 'member.login_id' mysql> INSERT INTO reservation VALUES (999,1,99,'2026-10-09',5); ERROR 1452 (23000): Cannot add or update a child row: a foreign key constraint fails (`sportdb`.`reservation`, CONSTRAINT `reservation_ibfk_2` FOREIGN KEY (`facility_id`) REFERENCES `facility` (`facility_id`)) mysql> DELETE FROM facility WHERE facility_id=1; ERROR 1451 (23000): Cannot delete or update a parent row: a foreign key constraint fails (...) mysql> INSERT INTO facility VALUES (8,'테스트','달서구','비싸요',TRUE); ERROR 1366 (HY000): Incorrect integer value: '비싸요' for column 'fee' at row 1

번호무엇을 어겼나어디를 고치나
1062기본키 또는 UNIQUE 중복넣으려는 값
1048NOT NULL 인데 비움빠뜨린 칸
1452없는 부모를 가리킴가리키는 번호
1451자식이 있는 부모를 지움자식을 먼저 지우거나 남겨 둠
1366자료형이 안 맞음값 또는 열의 자료형
1452 와 1451 은 이름이 비슷해 헷갈립니다. 방향이 반대입니다. 1452 는 없는 것을 가리키려다 막힌 것이고, 1451 은 누가 가리키고 있는 것을 지우려다 막힌 것입니다. 앞은 넣을 때, 뒤는 지울 때 납니다.

자료형 고르기

담을 것자료형
번호 · 개수 · 금액INT 계산할 것이면 숫자로
이름 · 주소VARCHAR(n)길이를 정합니다
날짜DATE 글자로 넣으면 날짜 계산이 안 됩니다
예 / 아니오BOOLEAN MySQL 은 내부적으로 TINYINT 로 저장해 1 · 0 으로 보입니다

전화번호는 숫자처럼 보이지만 VARCHAR 로 잡습니다. 010-1234-5678 에는 하이픈이 들어가고, 숫자로 담으면 맨 앞 0 이 사라집니다. 더할 일도 뺄 일도 없으니 글자로 두는 편이 맞습니다.

14테이블 조작

CRUD 넷과 조인 하나면 됩니다.

근거

학습모듈 3-3

용어

SQL · CRUD

넣기

INSERT INTO facility VALUES (1,'중앙체육관','달서구',2000,TRUE); INSERT INTO facility VALUES (2,'달성운동장','달성군',1500,FALSE); INSERT INTO facility VALUES (3,'수성풋살장','수성구',3000,FALSE); INSERT INTO member VALUES (1,'kim','김민수'); INSERT INTO member VALUES (2,'park','박정희'); INSERT INTO reservation VALUES (101,1,1,'2026-10-01',10); INSERT INTO reservation VALUES (102,2,3,'2026-10-02',8); INSERT INTO reservation VALUES (103,1,3,'2026-10-05',12);

순서가 있습니다. 예약은 회원과 시설을 가리키므로 그 둘이 먼저 있어야 합니다. 거꾸로 넣으면 앞 실습에서 본 1452 오류가 납니다.

읽기

mysql> SELECT * FROM facility; +-------------+-----------------+-----------+------+--------+ | facility_id | name | region | fee | indoor | +-------------+-----------------+-----------+------+--------+ | 1 | 중앙체육관 | 달서구 | 2000 | 1 | | 2 | 달성운동장 | 달성군 | 1500 | 0 | | 3 | 수성풋살장 | 수성구 | 3000 | 0 | +-------------+-----------------+-----------+------+--------+

indoor 가 1 과 0 으로 보입니다. BOOLEAN 으로 만들었는데 MySQL 이 TINYINT 로 저장하기 때문입니다. 값은 제대로 들어가 있으니 놀랄 일은 아닙니다.

SELECT name, fee FROM facility WHERE fee <= 2000 ORDER BY fee;

이어 읽기

예약 표에는 번호만 들어 있습니다. member_id 가 1 이라고만 적혀 있지 그 사람이 누구인지는 없습니다. 이름까지 같이 보려면 회원 표와 이어야 합니다. 그 일을 하는 것이 조인입니다.

mysql> SELECT r.reservation_id, m.name AS 회원, f.name AS 시설, -> r.use_date, r.headcount -> FROM reservation r -> JOIN member m ON r.member_id = m.member_id -> JOIN facility f ON r.facility_id = f.facility_id -> ORDER BY r.reservation_id; +----------------+-----------+-----------------+------------+-----------+ | reservation_id | 회원 | 시설 | use_date | headcount | +----------------+-----------+-----------------+------------+-----------+ | 101 | 김민수 | 중앙체육관 | 2026-10-01 | 10 | | 102 | 박정희 | 수성풋살장 | 2026-10-02 | 8 | | 103 | 김민수 | 수성풋살장 | 2026-10-05 | 12 | +----------------+-----------+-----------------+------------+-----------+

ON 뒤가 어느 칸끼리 이을지를 적는 자리입니다. ERD 에서 그은 관계선이 그대로 여기로 옵니다. 선을 제대로 그려 두었으면 조인문은 옮겨 적기만 하면 됩니다.

모아 세기

SELECT f.name, COUNT(*) AS 건수, SUM(r.headcount) AS 총인원 FROM reservation r JOIN facility f ON r.facility_id = f.facility_id GROUP BY f.name ORDER BY 건수 DESC;

이 결과에 달성운동장은 나오지 않습니다. 예약이 한 건도 없어 조인에서 빠지기 때문입니다. 예약이 없는 시설까지 0 으로 보고 싶다면 LEFT JOIN 을 씁니다.

고치기와 지우기

UPDATE facility SET fee = 2500 WHERE facility_id = 1; DELETE FROM reservation WHERE reservation_id = 103;

WHERE 를 빠뜨리면 전부 바뀝니다. UPDATE facility SET fee = 2500; 는 모든 시설의 요금을 2500 으로 바꾸고, DELETE FROM reservation; 은 예약을 전부 지웁니다. 오류도 나지 않습니다. 고치거나 지우기 전에 같은 WHERE 로 SELECT 를 먼저 돌려 몇 건이 걸리는지 보는 습관을 들이십시오.

실습 1 한 줄만 바꿔 1,500배를 직접 잰다

목적 — 자료구조를 고르는 일이 왜 중요한지 말로 들으면 잘 안 와닿습니다. 같은 기능을 두 가지로 만들어 재 보면 그다음부터는 설명이 필요 없습니다. 이 교과의 첫 실습을 재는 일로 시작하는 까닭입니다.

절차 1 — 잴 프로그램을 쓴다

Cmp2.java import java.util.*; public class Cmp2 { public static void main(String[] a) { int N = 200_000, 찾을횟수 = 20_000; ArrayList<String> list = new ArrayList<>(); HashMap<String,Integer> map = new HashMap<>(); for (int i = 0; i < N; i++) { list.add("id" + i); map.put("id" + i, i); } Random r = new Random(42); String[] 찾을것 = new String[찾을횟수]; for (int i = 0; i < 찾을횟수; i++) 찾을것[i] = "id" + r.nextInt(N); int c = 0; long t = System.nanoTime(); for (String k : 찾을것) if (list.contains(k)) c++; long 리스트 = (System.nanoTime() - t) / 1_000_000; int d = 0; t = System.nanoTime(); for (String k : 찾을것) if (map.containsKey(k)) d++; long 맵 = (System.nanoTime() - t) / 1_000_000; System.out.println("자료 " + N + "개에서 " + 찾을횟수 + "번 찾기"); System.out.printf("ArrayList.contains %6d ms (찾은 것 %d개)%n", 리스트, c); System.out.printf("HashMap.containsKey %6d ms (찾은 것 %d개)%n", 맵, d); if (맵 > 0) System.out.println("차이 약 " + (리스트 / 맵) + "배"); } }

new Random(42) 의 숫자에 뜻이 있습니다. 씨앗을 고정하면 몇 번을 돌려도 같은 값을 찾습니다. 양쪽이 똑같은 것을 찾아야 견줄 수 있습니다.

절차 1 — 같은 것을 넣고 순서를 본다

Deque<String> 스택 = new ArrayDeque<>(); for (String s : new String[]{"가","나","다"}) 스택.push(s); while (!스택.isEmpty()) System.out.print(스택.pop() + " "); Queue<String> 큐 = new LinkedList<>(); for (String s : new String[]{"가","나","다"}) 큐.offer(s); while (!큐.isEmpty()) System.out.print(큐.poll() + " ");

절차 2 — 빈 것에서 꺼내 본다

절차 3 — 반복문 안에서 지워 본다

List<Integer> v = new ArrayList<>(List.of(1,2,3,4,5)); for (Integer x : v) if (x % 2 == 0) v.remove(x); java.util.ConcurrentModificationException

v.removeIf(x -> x % 2 == 0); [1, 3, 5]

한 줄로 끝납니다. 조건에 맞는 것을 지우고 싶으면 이 메서드를 쓰십시오. 반복자를 직접 써서 it.remove() 를 부르는 방법도 있지만 길고 틀리기 쉽습니다.

절차 1 — 클래스를 두 개 만든다

담는 것은 똑같이 아이디 하나입니다. 아래쪽에만 메서드 둘이 더 있습니다.

절차 2 — 같은 아이디를 두 번 넣는다

위쪽이 틀린 답입니다. Set 은 겹치는 것을 안 받는 자루인데 같은 아이디가 둘 들어갔습니다. 넣어 둔 것을 찾지도 못합니다. 예외는 한 줄도 안 났습니다.

이것이 이 교과에서 가장 조심해야 할 종류의 오류입니다. 터지면 자리를 알려 주지만, 조용히 틀리면 알려 주는 것이 없습니다. 중복 신청을 막으려고 HashSet 을 썼는데 안 막히는 상황을 생각해 보십시오. 코드를 아무리 들여다봐도 잘못이 안 보입니다.

record 로 만들면 equals 와 hashCode 를 자바가 만들어 줍니다. 값만 담는 클래스라면 이쪽이 안전합니다. IDE 에서 두 메서드를 생성하는 기능을 써도 됩니다. 직접 손으로 쓰는 일은 거의 없습니다.

절차 5 — 꺼내는 순서를 견준다

다 · 가 · 나 · 라 를 차례로 넣고 키를 꺼내면 HashMap [가, 다, 나, 라] LinkedHashMap [다, 가, 나, 라] TreeMap [가, 나, 다, 라]

HashMap 의 순서는 넣은 순서도 아니고 가나다순도 아닙니다. 해시 값이 정한 자리 순서입니다. 자바 판이 바뀌거나 자료가 늘어나면 달라질 수 있으므로 이 순서에 기대는 코드를 쓰면 안 됩니다.

선형과 비선형

여기까지 본 것은 전부 한 줄로 늘어섭니다. 배열도 리스트도 스택도 큐도 앞뒤가 하나씩입니다. 이것을 선형 구조라 합니다. 트리와 그래프는 한 칸에서 여러 갈래로 갈라집니다.

트리 그래프 A A ─── B / \ │ │ B C C ─── D / \ \ / D E E ─── F 갈라지기만 하고 돌아오지 않음 돌아올 수 있음 위로는 하나뿐 이웃이 여럿

트리가 쓰이는 자리

보기
폴더 구조폴더 안에 폴더. 위로는 하나뿐입니다
HTML 문서태그 안에 태그. 화면 구현 교과에서 다룹니다
조직도 · 분류 체계NCS 의 대분류 · 중분류 · 소분류가 트리입니다
TreeMap키를 정렬된 트리로 담아 범위를 자를 수 있습니다

TreeMap 에 10 · 25 · 37 · 48 · 52 를 넣어 두면 subMap(25, 48) {25=나, 37=다} 범위로 자릅니다 floorKey(30) 25 30 바로 아래 ceilingKey(30) 37 30 바로 위

HashMap 으로는 이것을 못 합니다. 순서가 없기 때문입니다. 날짜 범위 조회 같은 기능이 있으면 TreeMap 쪽입니다.

그래프를 도는 두 방법

쓰는 자료구조
너비 우선 탐색큐 가까운 것부터 훑습니다. 최단 거리를 찾을 때
깊이 우선 탐색스택 한 갈래를 끝까지 따라갑니다. 경로가 있는지 볼 때

같은 그래프를 돌면서 자료구조만 큐에서 스택으로 바꾸면 A B C D E F 가 A B D E C F 로 바뀝니다. 나머지 코드는 한 줄도 안 고칩니다. 자료구조를 고르는 일이 곧 알고리즘을 고르는 일이 되는 예입니다 — 실습 7.

이 교과에서 그래프를 깊이 다루지 않습니다. 최단 경로 알고리즘이나 신장 트리는 범위 밖입니다. 비선형 구조가 무엇인지 알고, 큐와 스택이 순회 순서를 바꾼다는 것을 직접 보면 됩니다.
실습 7 같은 그래프를 큐와 스택으로 돌아 순서를 바꿔 본다

목적 — 자료구조를 고르는 일이 알고리즘을 고르는 일이 되는 자리를 한 번 보여 주려는 실습입니다. 코드를 한 줄도 안 고치고 담는 그릇만 바꾸면 도는 순서가 달라집니다.

절차 1 — 그래프를 만든다

static Map<String,List<String>> 이웃 = new LinkedHashMap<>(); static void 잇기(String a, String b) { 이웃.computeIfAbsent(a, k -> new ArrayList<>()).add(b); 이웃.computeIfAbsent(b, k -> new ArrayList<>()).add(a); } 잇기("A","B"); 잇기("A","C"); 잇기("B","D"); 잇기("C","E"); 잇기("D","E"); 잇기("E","F");

이웃 목록 A → [B, C] B → [A, D] C → [A, E] D → [B, E] E → [C, D, F] F → [E]

그래프를 담는 가장 흔한 방법이 이것입니다. 칸마다 이웃 목록을 달아 둡니다. LinkedHashMap 을 쓴 것은 찍을 때 넣은 순서대로 보려는 것뿐입니다.

절차 2 — 큐로 돈다

Set<String> 봤다 = new LinkedHashSet<>(); Deque<String> q = new ArrayDeque<>(); q.offer("A"); 봤다.add("A"); while (!q.isEmpty()) { String c = q.poll(); System.out.print(c + " "); for (String n : 이웃.get(c)) if (봤다.add(n)) q.offer(n); } 너비 우선(큐) : A B C D E F

봤다.add(n) 이 참을 돌려주면 처음 본 것이라는 뜻입니다. Set 의 add 는 이미 있으면 거짓을 줍니다. 이 한 줄로 확인과 표시를 같이 합니다. 안 하면 A 와 B 사이를 무한히 오갑니다.

절차 3 — 스택으로 돈다

Deque<String> s = new ArrayDeque<>(); s.push("A"); while (!s.isEmpty()) { String c = s.pop(); if (!봤다2.add(c)) continue; System.out.print(c + " "); List<String> n = new ArrayList<>(이웃.get(c)); Collections.reverse(n); for (String m : n) if (!봤다2.contains(m)) s.push(m); } 깊이 우선(스택) : A B D E C F

절차 4 — 두 순서를 견준다

너비 우선(큐) : A B C D E F 깊이 우선(스택) : A B D E C F

자료구조도는 모양
너비 우선큐 A 의 이웃 B · C 를 먼저 다 보고 그다음 층으로
깊이 우선스택 A 에서 B 로, B 에서 D 로 끝까지 따라갑니다

큐는 먼저 넣은 것이 먼저 나오니 가까운 것부터 처리됩니다. 스택은 마지막에 넣은 것이 먼저 나오니 방금 간 길을 계속 따라갑니다. 알고리즘 이름이 두 개지만 차이는 그릇 하나입니다.

스택 쪽에 Collections.reverse 가 들어간 것은 보기 좋게 하려는 것입니다. 스택은 나중에 넣은 것이 먼저 나오므로 이웃을 순서대로 넣으면 뒤에서부터 돕니다. 뒤집어 넣으면 앞에서부터 도는 모양이 됩니다. 빼고 돌리면 A C E F D B 가 나옵니다. 순서는 달라도 한 갈래를 끝까지 따라가는 모양은 같습니다.
절차 5 — TreeMap 으로 범위를 잘라 본다

TreeMap<Integer,String> t = new TreeMap<>(); t.put(10,"가"); t.put(25,"나"); t.put(37,"다"); t.put(48,"라"); t.put(52,"마"); 전체 {10=가, 25=나, 37=다, 48=라, 52=마} 25 이상 48 미만 {25=나, 37=다} 30 바로 아래 25 30 바로 위 37 가장 작은 키 10

TreeMap 은 속이 트리라 키가 정렬된 채로 있습니다. 그래서 범위를 자를 수 있습니다. 같은 것을 HashMap 으로 하려면 전부 훑어 걸러야 합니다.

순서가 교안과 다르다 이웃 목록에 넣은 순서가 다릅니다. 절차 1 을 그대로 하십시오
같은 칸이 두 번 찍힌다 스택 쪽은 꺼낸 뒤에 표시해야 합니다 — 절차 3

버블 정렬

안쪽 반복문의 끝이 - i 로 줄어드는 것에 주의하십시오. 한 바퀴 돌 때마다 맨 뒤 한 칸이 확정되므로 다음 바퀴에서는 볼 필요가 없습니다. 이 - i 를 빠뜨리면 답은 맞는데 두 배쯤 느려집니다.

선택 정렬

for (int i = 0; i < v.length - 1; i++) { int m = i; for (int j = i + 1; j < v.length; j++) { 비교++; if (v[j] < v[m]) m = j; } 자리바꿈(v, i, m); 교환++; }

안쪽에서는 자리를 바꾸지 않고 가장 작은 것의 번호만 기억합니다. 바깥에서 한 번만 바꿉니다. 그래서 2만 개를 정렬해도 교환이 19,999번뿐입니다.

삽입 정렬

for (int i = 1; i < v.length; i++) { int k = v[i], j = i - 1; while (j >= 0) { 비교++; if (v[j] <= k) break; v[j+1] = v[j]; 교환++; j--; } v[j+1] = k; }

안쪽이 while 이고 break 가 있는 것이 핵심입니다. 제자리를 찾으면 바로 멈춥니다. 그래서 이미 정렬된 자료에서는 한 번씩만 견주고 끝납니다.

비교 횟수를 세는 자리를 정확히 잡아야 합니다. while 조건 안이 아니라 몸통 첫 줄에서 세십시오. 조건에서 세면 반복이 끝날 때 한 번 더 세어 숫자가 어긋납니다. 제출한 숫자가 이론값과 안 맞으면 대개 세는 자리가 틀린 것입니다.

목적 — 시간을 재면 컴퓨터마다 다릅니다. 비교 횟수는 어느 컴퓨터에서 세도 같습니다. 탐색은 비교 횟수로 견주는 편이 훨씬 설명하기 쉽습니다.

절차 1 — 선형 탐색

static int 선형(int[] v, int k) { int c = 0; for (int x : v) { c++; if (x == k) break; } return c; }

찾은 자리가 아니라 견준 횟수를 돌려줍니다. 실무 코드라면 자리를 돌려주겠지만 여기서는 세는 것이 목적입니다.

못 찾았을 때 무엇을 돌려줄지 정해 두어야 합니다

절차 5 — 안정 정렬이 언제 필요한지 안다

① 이름순으로 정렬해 둡니다 ② 다시 날짜순으로 정렬합니다 안정적이면 같은 날짜 안에서 이름순이 지켜집니다 아니면 같은 날짜 안의 순서가 뒤죽박죽이 됩니다

깃발 변수가 흐름을 이끕니다

리팩토링을 배우는 자리에서 가장 먼저 부딪히는 물음이 이것입니다. 잘 돌아가는 코드를 왜 건드리느냐는 물음인데, 답은 두 가지입니다. 하나는 다음에 고칠 때 드는 시간이고, 다른 하나는 위 상자에서 본 것처럼 숨어 있는 위험입니다.

가독성은 이름에서 갈립니다

data → facilities 무엇이 담겼는지 count → acceptedCount 무엇을 센 것인지 p → parts 쪼갠 조각 ok → (없앰) 깃발 대신 이른 반환 LASTERROR → (없앰) 돌려주는 값으로 바꿈

아래 두 줄은 이름을 고치는 쪽이 아니라 아예 없애는 쪽입니다. 좋은 이름을 못 찾겠으면 그 변수가 필요 없는 경우가 많습니다.

중복을 찾습니다

for (int i = 0; i < data.size(); i++) { if (data.get(i)[0].equals(facility)) { ... } } for (int i = 0; i < data.size(); i++) { if (data.get(i).length > 3 && data.get(i)[3].equals(day)) { ... } } 시설 자료를 훑는 일이 두 번 나옵니다

둘 다 시설 자료를 훑습니다. 시설 자료를 다루는 일은 시설 자료를 가진 쪽으로 옮기는 편이 낫습니다.

이것이 실습 10 에서 다루는 메서드 이동입니다. 자료가 있는 곳에 그 자료를 다루는 메서드를 두면 훑는 코드가 한 곳에 모입니다. 정적모델 설계 교과에서 자료와 그에 딸린 동작을 함께 묶는다고 한 말이 실제로 무엇을 뜻하는지 이 자리에서 드러납니다.

데이터베이스는 문자열을 받아서 해석합니다. 값과 명령이 한 문자열에 섞여 있으면 어디까지가 값인지 따옴표로만 가릅니다. 그 따옴표를 입력이 닫아 버리면 나머지는 명령이 됩니다.

자리를 비워 두고 값을 따로 넘깁니다

public class ReservationSql { public static final String INSERT = "INSERT INTO reservation VALUES (?, ?, ?)"; private final List<String> values = new ArrayList<>(); public ReservationSql bind(String value) { values.add(value); return this; } public String text() { return INSERT; } public List<String> values() { return values; } @Override public String toString() { return INSERT + " <- " + values; } }

뒤의 두 메서드는 나중에 쓸 것 같아서 미리 만들어 둔 것입니다. 실습 15 에서 이 둘이 어떻게 되는지 보십시오.

명령은 INSERT 에 박혀 있고 값은 values 에 따로 담깁니다. 둘이 한 문자열로 합쳐지는 일이 없으므로 입력이 명령이 될 길이 없습니다.

부르는 쪽

private static ReservationSql buildSql(String member, String facility, String day, String time) { return new ReservationSql() .bind(member) .bind(facility) .bind(day + " " + time); }
